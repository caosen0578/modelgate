# Spec Me2AI · 05 · 边界限制与禁止规则

> **文档性质**：人工编写，AI 严格遵守，每条规则均为红线，不得以任何理由绕过

---

## 1. 功能边界（禁止超范围实现）

| 禁止实现 | 原因 |
|---|---|
| 模型训练、微调、Fine-tuning | 不在本系统职责范围 |
| 用户个人账号体系（登录/注册/密码） | 不是 C 端产品，无用户维度 |
| 跨公司/跨外网访问能力 | 内网网关，不对外暴露 |
| 计费、账单、支付 | v1 不实现，Token 统计仅用于审计 |
| 模型推理能力（直接调用 GPU） | 只做流量转发，不做推理 |
| 多租户/多工作空间 | 单租户内网产品 |
| 前端 SPA 路由（React/Vue）| 管理后台用服务端渲染 HTML 或静态页面 |

## 2. 技术选型红线（禁止引入）

### 2.1 ORM 框架禁令

```
禁止引入：
  - JPA / Spring Data JPA
  - Hibernate
  - JOOQ
  - Ebean
  - 原生 MyBatis（XML Mapper 方式）

必须使用：MyBatis Plus 3.5.9（LambdaQueryWrapper，无 XML）
```

### 2.2 框架版本禁令

```
禁止：
  - 降级 Spring Boot 至 2.x（必须 3.3.5）
  - 降级 JDK 至 8 或 11（必须 JDK 17）
  - 引入 Zuul（必须使用 Spring Cloud Gateway）
  - 使用 Hystrix（必须使用 Resilience4j）
  - 使用 RabbitMQ / RocketMQ（必须使用 Kafka）
```

### 2.3 缓存架构禁令

```
禁止：
  - 只用单层 Redis（必须 Caffeine L1 + Redis L2 双层）
  - 只用单层 Caffeine（Redis L2 用于跨实例同步）
  - 在 Filter 中穿透 DB（Redis 故障时 L1 miss 直接拒绝）
```

### 2.4 构建工具禁令

```
禁止：切换至 Gradle（必须使用 Maven）
```

## 3. 包结构禁令

```
禁止：
  - 在 com.pab.ficc.idp.modelgate 下新增顶级包
  - 将 Filter 类放在 filter/ 包以外的位置
  - 将 DAO 类放在 persistence/ 包以外的位置
  - 将 Entity 类放在 entity/ 包以外的位置
  - 在 entity/ 包中放非 POJO 类（禁止包含业务逻辑）
```

## 4. 安全红线

### 4.1 密钥处理禁令

```
禁止：
  - 在数据库中明文存储上游 API Key / SK（必须 AES-256-GCM 加密）
  - 在数据库中存储 API Key 原文（必须存 SHA-256 hash）
  - 在日志中打印完整 API Key / SK / 密码（末4位可见）
  - 将加密密钥硬编码在代码中（必须从环境变量读取）
  - 在 HTTP 响应中二次返回 API Key 原文（只在创建时返回一次）
```

### 4.2 鉴权绕过禁令

```
禁止：
  - 在非 /actuator/health 和 /actuator/info 路径上跳过 AdminAuthFilter
  - 使用字符串 equals 比对 API Key（必须 MessageDigest.isEqual 常量时间）
  - 跳过 AK/SK 时间戳防重放校验（窗口 ±5min）
  - 在 CredentialAuthFilter 内读取 DB 时不切换 boundedElastic 线程池
```

### 4.3 SQL 安全禁令

```
禁止：
  - 字符串拼接 SQL（必须 MapSqlParameterSource 参数化）
  - SELECT *（必须明确列出查询字段）
  - 在非 DAO 层执行 SQL
```

## 5. WebFlux 线程模型禁令

```
禁止：
  - 在 GlobalFilter 中调用同步 JDBC（不经 Schedulers.boundedElastic 包裹）
  - 在 Filter 中使用 Thread.sleep()
  - 在响应式链中使用 .block() / .blockFirst() / .blockLast()
  - 在 Netty 事件循环线程中执行任何 IO 操作
```

正确模式：
```java
Mono.fromCallable(() -> jdbcCall())
    .subscribeOn(Schedulers.boundedElastic())
    .flatMap(result -> chain.filter(exchange))
```

## 6. Filter 执行顺序保护

```
禁止：
  - 更改任意 Filter 的 order 值（见 02-架构设计.md 第3节）
  - 在 CredentialAuthFilter 之前增加依赖凭证信息的 Filter
  - 在 ModelRouteFilter 之后增加读取原始请求体的 Filter
  - 跳过 AdminAuthFilter 直接访问 /admin/**
```

---

## 7. 缓存操作禁令

```
禁止：
  - 在 Service 层直接操作 Caffeine 缓存（必须通过 GatewayCacheManager）
  - 在 Controller 层直接操作缓存
  - 缓存失效时采用懒失效（写操作必须主动失效缓存）
  - Redis 故障时穿透 DB（L1 miss + Redis 故障 → 直接拒绝，不查 DB）
```

---

## 8. 业务规则禁令

```
禁止：
  - 删除存在活跃授权的模型（必须先撤销所有授权）
  - 将 API Key 原文返回给查询接口（查询只返回末4位 + ***）
  - 级联禁用模型时跳过 App 下凭证的失效（App 禁用 → 该 App 所有凭证立即失效）
  - 授权过期后自动删除记录（过期仅等同禁用，不删除记录）
  - 在访问控制规则为空时拒绝请求（规则为空 = 不限制来源）
```

---

## 9. 接口设计禁令

```
禁止：
  - 更改 /v1/chat/completions 的路径（与 OpenAI SDK 兼容）
  - 更改 /admin/** 下任何已定义接口的 HTTP 方法或路径
  - 在响应中使用非标准 HTTP 状态码（只用 200/400/401/403/429/500/503）
  - Controller 方法返回裸 T 类型（必须 Mono<Result<T>>）
  - 在 Result 以外的位置包装业务数据
```

---

## 10. 代码质量禁令

```
禁止：
  - 在 Entity 类中添加任何框架注解（@Entity/@Table/@Column 等）
  - 在 Service 层写 SQL
  - 新增 BusinessException 子类（统一使用 BusinessException(ErrorCode)）
  - 在非 Filter 层直接向 response 写入数据（响应体写入只在 Filter 和 GlobalExceptionHandler）
  - 使用 System.out.println 打印日志
  - Entity 的时间字段使用 java.util.Date（必须 LocalDateTime）
```
