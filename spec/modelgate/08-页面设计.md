## P2 模型管理 `/models`

**列表页**

| 列 | 说明 |
|---|---|
| 模型 ID | 网关对外暴露的路由标识，带复制按钮 |
| 名称 | 展示名 |
| 提供商 | 带图标 |
| 类型 | Chat / Embedding 等 |
| API 规范 | openai / anthropic 等 |
| 状态 | 启用/禁用/维护中，带颜色标签 |
| 今日调用 | 当日请求数 |
| 操作 | 编辑 \| 测试连通 \| 启用禁用 \| 删除 |

**新增/编辑弹窗（分步表单，共 3 步）**

```
步骤 1：基础信息
  - 模型 ID（网关对外 ID，新增/编辑均可修改；改名需二次确认）
  - 上游真实模型 ID（供应商原始 ID；留空表示与模型 ID 相同）
  - 名称、提供商（选择后自动填充默认上游地址）
  - 模型类型、描述

步骤 2：连接配置
  - 上游地址
  - API 规范（选择后显示对应的说明文字）
  - 鉴权类型 + 对应的密钥输入框
    api_key   → [API Key 输入框]
    ak_sk     → [Access Key] + [Secret Key]
    azure     → [API Key] + [Resource Name] + [Deployment ID] + [API Version]
    none      → 无需配置
  - 超时时间

步骤 3：参数配置
  - 默认参数（JSON 编辑器，带格式校验）
  - 强制参数（JSON 编辑器）
  - 自定义映射（api_spec=custom 时展示，JSON 编辑器）
  
  [测试连通] 按钮 → 显示测试结果（延迟、响应预览）
```

**🧪 模型测试工具**

- 下拉框选择的是网关对外 `modelId`，页面同时明确展示实际发送的 `upstreamModelId`。
- 原始测试请求体中的 `model` 使用上游真实 ID；额外参数中的同名字段不得覆盖它，服务端还须按库中配置二次校正。
- 快速连通性测试、保存前草稿测试和对话测试都验证真实上游 ID，并应用默认参数、强制参数与字段映射。
- 管理面测试跳过接入系统鉴权/授权/配额，只验证模型层配置；该说明必须在页面保留。

## P5 审计日志 `/audit`

```
用量统计卡片（页面顶部，进入页面 / 点击查询时自动刷新）：
┌────────────────┐ ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
│  📊 总请求数   │ │ 🔤 总Token消耗  │ │  ⚡ 平均延迟   │ │   ✅ 成功率    │
│   128,432      │ │     3.2M       │ │    342ms       │ │    99.2%       │
└────────────────┘ └────────────────┘ └────────────────┘ └────────────────┘
（来源：GET /modelgate/stats/usage?appId=&modelId=，支持按接入系统 / 模型维度筛选）

筛选条件：
[时间范围] [接入系统▼] [appId] [应用编码] [模型▼] [状态▼] [搜索 TraceID]  [查询]

表格（分页，共 10 列）：
时间              | TraceID | 应用 appId | 应用编码  | 模型    | IP           | 状态 | 延迟  | Tokens | 操作
2026-04-23 10:01  | abc123  | crm-svc    | CRM001   | gpt-4o  | 10.0.1.5     | 200  | 342ms | 1,204  | 📨 报文
2026-04-23 10:01  | def456  | bi-svc     | BI001    | claude  | 192.168.1.9  | 429  | 12ms  | -      | 📨 报文

> 列名用「应用 appId」而不是「接入系统」：这一列的值就是 `app_id`，叫"系统"会和
> `system_name` / `sys_code` 混淆（一个业务系统下可以登记多个应用，见 P3）。
> 「应用编码」= `mg_app.app_code`，**不在审计表里**，由服务端按当前页 appId 批量反查后回填；
> 应用已删除时显示 `-`。报文列表同此规则。
> ⚠️ 加列时空态 `colspan` 必须同步（审计 9→10、报文 12→13），HTML 静态空态与
> JS 里动态生成的空态**是两处**，容易只改一处。

[点击行] → 展开详情：请求参数（脱敏）、响应摘要、完整错误信息
```

**接口说明：**

| 操作 | 接口 | 说明 |
|---|---|---|
| 用量统计 | `GET /modelgate/stats/usage` | 返回 totalRequests / totalInputTokens / totalOutputTokens / avgLatencyMs / successRate；支持 `appId` / `appCode` / `modelId` 过滤 |
| 审计明细 | `GET /modelgate/audit/query` | 分页返回审计记录；支持 appId / appCode / modelId / httpStatus / traceId 过滤 |

**appId 与应用编码筛选（审计页与报文页共用同一套交互）**

- 「接入系统」下拉**只是挑选器**，选中后把 appId 回填到右边的 appId 输入框；
  **真正提交的是输入框**。两个控件提交同一个参数会互相打架，必须只有一个是真值。
- 之所以不止保留下拉：下拉一次只拉 200 个应用（`pageSize=200`），应用多了想筛的那个可能压根不在里面；
  而排查时手上通常直接就有 appId 或应用编码。
- 手输 appId 后若与下拉当前选中值不一致，下拉自动复位为「全部系统」，避免"下拉显示 A、输入框写着 B"的矛盾状态。
- 「应用编码」为**精确匹配**，一个编码可能对应多个应用（会一并查出）；与 appId 同时填写按**与**处理。
  解析语义见 [04 §2.10](./04-接口与数据结构.md)。
- 统计卡片与列表**同口径**：卡片也带 `appCode`，否则会拿全量汇总去解释按编码筛出来的列表。
- 从报文详情跳回审计（按 traceId 定位）时，**appId / 应用编码 / 模型 / 状态一律清空**——
  漏清会与 traceId 取交集，表现为"点了跳转却什么都没有"，而用户并不知道是被上一次筛选挡掉的。

> 页面切换即加载对应数据，不再有"先连接后使用"这一步。

## P7 报文记录 `/payload`

- 筛选区提供「接入系统▼ / appId / 应用编码 / 模型▼ / TraceID / 类型 / 上游状态码 / 结束原因 / 完整性」
  以及「请求报文 / 请求头」范围选择加一个全模糊关键字输入框；关键字一次只激活一种检索，
  防止同一条 SQL 重复扫描两个大字段。
- appId 与应用编码的交互与审计页完全一致（下拉回填输入框、编码精确匹配、与 appId 取交集），
  见 P5 的说明；应用编码**不能**充当模糊关键字的收窄条件。
- 模糊检索必须搭配 ≥8 位 TraceID 或两端齐全且跨度 ≤24 小时的时间范围；请求头关键字至少3字符。
- 页面从 `/modelgate/payload/meta` 回显请求头单值/总字符上限，并明确提示“全部请求头留档，包含凭证”。
- 列表增加请求头 JSON 预览；详情弹窗增加「请求头」Tab，与请求报文、响应正文、响应原文分开渲染。
  请求头 Tab 展示全部入站 Header，包括 Authorization/Cookie/API Key/Token/JWT/签名等凭证字段。
- 请求头列表列固定为 140px 短预览，完整值通过悬浮提示或详情页查看，避免挤压请求报文和响应正文。
- 报文详情的「响应正文」结构化为“消息内容 → 工具调用明细 → OpenAI 工具调用基础校验”；每项工具
  调用分别展示 ID、类型、工具名称和格式化参数。支持 OpenAI SSE `delta.tool_calls` 分片合并与
  Anthropic `tool_use/input_json_delta`，纯工具调用、正文为空时仍能看到参数。
- OpenAI 基础校验检查 `tool_calls/id/type=function/function.name/arguments`、`finish_reason=tool_calls`
  与 SSE `[DONE]`；页面明确说明不是完整 OpenAI Schema 校验，Anthropic 原生协议显示为“不适用”。
- 工具调用只在用户打开「响应正文」时由管理页懒解析并缓存；不新增数据库字段，不进入转发热路径。

## P8 服务管理 `/services`（2026-08-27 新增）

与「模型管理」平级的第二类上游目标。

**列表列**：服务编码 / 名称 / 对外路径（可一键复制）/ 上游地址 / 剥离前缀 / 探测方式 / SSE /
报文留档 / 上游鉴权 / 授权系统数（可点击反查）/ 状态 / 操作（🧪 测试 / 编辑 / 启停 / 删除）

**新增·编辑弹窗**要点：
- **只填「服务编码」这一个短标识**，`/svc/` 由网关拼——不让运营手写整个前缀，
  避免 `svc/crm`、`/svc/crm`、`/svc/crm/` 三种写法造成匹配歧义。编辑时该字段置灰
- **实时转发预览**：填完编码与上游地址即时显示「调用方请求 X → 网关实际转发 Y」。
  路径规则是这里最容易理解错的地方，直接显示结果比写多少说明都有效
- 连通性探测配置（方法 + 路径 + 请求体）：非 GET 时展开请求体输入并显示副作用警告
- SK 与附加请求头**不回显**，留空 = 保持原值；要清空请把鉴权类型改成 `none`

**🧪 服务测试工具**：与「🧪 模型测试工具」同骨架（左配置 / 右结果双栏）。
左栏含目标服务、上游鉴权类型、探测方式（预填服务登记值、可临时覆盖）、
**实际探测地址实时预览**；右栏结论置顶 + 状态栏 + 上游原始返回可折叠。
左栏底部固定说明它与「接入示例 → 测试连通」**不是同一个问题**。

## P10 接入示例支持服务接口

凭证管理 → 接入示例弹窗加「接入类型」下拉：模型接口 `/v1/**` ↔ 服务接口 `/svc/{编码}/**`。

服务侧表单换成：调用服务 / 接口路径 / HTTP 方法 / 请求体，并给出**两跳地址实时预览**
（调用方 → 网关 / 网关 → 上游）。「接口路径」填的是**该服务自己接口原本的路径**，
即不走网关时直接调它用的那一段。

**服务侧没有「流式返回」勾选框**：SSE 与否由上游接口自己决定，网关只做透传，
勾一个复选框既不改变请求也不改变响应，摆在那里纯属误导——改为读服务的 `sse` 标记自动带 `-N`。

测试结果面板新增「**本次实际发出的请求**」折叠块，回显 method / URL / 请求头（Authorization 截断）/
完整请求体。排查"为什么返回的是流式/非流式"这类问题时，第一件要确认的就是请求体里到底有没有
`stream`，光看响应猜不出来。

任何请求参数变化（勾选流式 / 换模型或服务 / 改路径 / 改请求体 / 改网关地址）都会**立即收起旧的测试结果**——
否则面板里挂着上一次的结果，看起来就像"改了没生效"。

## P11 审计页 / 报文页的流量类型筛选

两页各加「流量类型」下拉（全部 / 模型 / 服务）与「服务编码」输入框，**默认不过滤**。

「模型」列改为「**模型 / 服务**」共用一列——一条记录只会有 `model_id` 或 `service_id` 其中一个，
加两列必然有一列恒空。服务流量在编码前加「服务」标签区分（两者命名空间独立，理论上可重名）。
