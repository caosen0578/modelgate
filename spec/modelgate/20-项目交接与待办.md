## 优先待办

### P0 排查行内约 60 秒的 Nginx 504

**现场现象**为直连模型约 1 分 40 秒完成，通过网关入口域名约 1 分钟收到 Nginx 超时。当前证据指向请求链路中的代理，具体设备和生效配置待现场确认。

| 层级 | 当前代码和核对点 |
|---|---|
| ModelGate 转发 | `spring.cloud.gateway.server.webflux.httpclient.response-timeout: 1800s` 等待上游 HTTP 响应头。SSE 响应头发出后，业务路由没有另设 chunk 间隔超时。连接建立 5 秒、获取连接池槽位 30 秒、空闲连接回收参数各有独立用途。模型转发无自动重试。 |
| 通用服务鉴权/转发 | `/modelgate/svc/**` 支持非阻塞 SSE 和普通 HTTP，转发保持流式。服务 `timeout_ms` 为正时，`ServiceRouteFilter` 按服务覆盖等响应头的时限。空值或非正值走全局配置。 |
| 前置代理 | 查实际域名及 `/modelgate` 命中规则的 SLB、Nginx/Ingress、上游代理及 idle/read timeout。独立 `gateway` 仓库的 60 秒配置仅在该请求确实经过它时适用。 |
| 管理工具 | 模型探测默认 10 秒、上限 15 秒。管理端模型对话测试后端默认 120 秒、上限 300 秒，分离前端普通 Axios 默认 30 秒。路径实测用接入示例「测试联调」或客户端直调公开业务接口。 |

## 已落地功能与维护入口

### 网关、协议与部署

- `ProviderAdapter` 已升级为适配器注册与统一请求/响应管线。已注册 OpenAI、Azure OpenAI、Anthropic、Custom 四类，支持 `PASSTHROUGH` 原生响应和适配器声明支持的 `OPENAI_COMPATIBLE` 响应。Custom 当前只声明原生透传。新增协议先核对适配器描述、路由和两套管理页的可选能力。
- 唯一外部文根是 `/modelgate`，由 `spring.webflux.base-path` 设置。Controller 保持相对映射，典型业务入口是 `/modelgate/v1/chat/completions` 和 `/modelgate/svc/{服务编码}/**`。
- `ModelGateApplication.main` 读取容器环境变量 `PORT_NO`。有效端口直接设置实际监听端口。变量缺失或空白时沿用配置的 `server.port`，仓库当前配置为 `8080`，行内可由 Apollo 下发。非法端口启动失败。Windows 用 `scripts/run-port-test.cmd` 临时验证，持久设置和删除分别用 `set-port-no.cmd` 与 `delete-port-no.cmd`。已启动的 IDEA 需重启或在 Run Configuration 设置环境变量。
- Nova 平台根据应用探针配置主动调用。使用实际监听端口与 `/modelgate/actuator/detection/{running,available,shutdown}`。另有 `/modelgate/actuator/health`。启动横幅和探针日志用于核查平台是否打到应用，摘流量与退出等待窗口在平台核验。
- 「网关配置」的 `gateway.public.base-url` 是对外发给调用方的固定模型接入地址。模型示例、复制与网关联调复用。管理页面访问地址和 SLB 路由继续由部署配置决定。
- 详细架构图与领导版都已保存。领导版按「网关、流量录制、流量回放」绘制。入口见 [architecture.html](../../src/main/resources/static/architecture.html) 和 [architecture-overview.html](../../src/main/resources/static/architecture-overview.html)。

实现和部署细节见 [适配器升级](./14-ProviderAdapter-V2升级.md)、[通用服务接入](./12-通用服务接入设计.md)、[统一文根](./15-统一文根与路径迁移.md)、[部署与运维](./10-部署与运维手册.md)、[架构图与录制回放](./16-架构图与报文录制回放.md)。

### 接入应用、接入用户与权限

- 分离前端的两个四字菜单为「接入应用」「接入用户」。个人主体在 `mg_app` 以 `subject_type=PERSONAL` 和 `person_um` 区分。后端分配 `P_` 加 32 位十六进制 UUID，共 34 字符，适配现有 `app_id VARCHAR(64)`，与业务录入的纯数字 AppID 分开。内部 AppID 用于复用凭证、授权和配额，统计按 UM。
- 「新增」按 UM 先查 CMS 人员目录，再按权限从 CMS 拉取。批量导入只建用户，列表勾选后用独立的批量模型授权，可选多个模型。共享 CMS 组件/API 位于 `src/components/CmsUserCreateDialog` 和 `src/api/modules/cmsUser.ts`，遵守 Vite ESLint 跨模块引用约束。
- 个人与应用页面均展示已授权模型和凭证数量，并提供凭证管理、接入示例和测试交互。接入应用另有服务授权与数量。复制兼容 HTTP。经授权可查看可找回的完整密钥，示例可主动填入真实密钥后直接分发。只有哈希的旧凭证需重新签发。凭证禁用、删除和显式明文操作分别核验权限。
- 个人访问控制对齐应用样式，含 IP/CIDR 和域名白名单。均为空时不限制来源。个人仅信任 `modelgate.personal-access.trusted-proxies` 指定代理的转发头。规则与模型授权提交后用 Redis 版本号协调多实例，本地缓存未命中时从数据库读取，个人历史 IP 规则同时做格式规范化。Token 累计和限流仍沿用网关现有链路。
- `modelgate.personal-access.enabled` 位于 ModelGate 的 `application.yml`。当前仓库值为 `true`，环境以生效配置为准，开启前完成网关库和授权增量。业务校验错误（例如授权时间已过期）需要在页面显示响应中的业务消息。

专项见 [个人接入](./17-个人接入与UM用量统计.md)、[模型对外接入地址](./18-模型对外接入地址需求评审稿.md)。分离前端从 `src/modules/modelgate/views/apps`、`personal-access`、`settings` 定位。

### 审计、报文与评测

- 个人请求进入审计。请求与响应报文是否记录由单项模型授权的开关控制，个人与应用入口都支持。审计、报文支持按接入主体、模型多选、UM 和时间筛选。UM 候选来自全量用户目录，显示 UM 及姓名。共同的时间范围控件支持本周、月、季度和向前逐期切换，所选起止回显。报文列表显示完整 TraceID，两个列表都可按筛选导出。
- 单条报文保留「回放」。批量路径在「报文记录」勾选可用模型报文，点击「批量评测」预检并保存评测集。由「模型评测」管理样本版本、运行目标模型、比对基线/历史响应、评分、重跑和导出。缺少勾选框时先核对当前角色的样本预检/保存权限及记录类型。
- 样本详情显示源报文主键和 TraceID，可跳回报文记录。参考答案初始取源响应正文，可编辑后发布 `v1`、`v2` 等版本。独立样本支持业务人员使用的 `.xlsx` 模板、预览和难度，也兼容 JSON/JSONL。模板由后端提供，Excel 预览依赖 Maven 的 `poi-ooxml`。遇到 IDE 编译缺包，先按项目 `pom.xml` 重新导入依赖并确认发布制品。
- 评测任务直连目标上游，评测 Token、状态、耗时和输出保存在 `mg_eval_*`，历史基线保留源流量的 Token 关联。常规审计、报文记录和用量看板按业务转发流量统计。

具体流程、Excel 字段和权限见 [批量模型评测](./19-批量模型评测.md)。分离前端维护入口为 `src/modules/modelgate/views/{audit,payload,evaluation}`。
