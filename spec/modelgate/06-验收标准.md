# Spec Me2AI · 06 · 验收标准

> **文档性质**：人工编写，AI 严格遵守，每个验收项必须可被测试验证

---

## 1. 模型管理验收

### 1.1 基础 CRUD

| # | 验收项 | 通过条件 |
|---|---|---|
| M-01 | 创建模型 | POST /admin/models 成功返回 200，DB 中有记录 |
| M-02 | 创建时指定 modelId 不可重复 | 重复 modelId 返回 400 |
| M-03 | 查询模型列表 | GET /admin/models 返回所有模型，含上游地址 |
| M-04 | 更新模型 | PUT 成功，上游地址修改后 30s 内网关生效 |
| M-05 | modelId 不可修改 | PUT 请求中修改 modelId 字段无效果（忽略或报错） |
| M-06 | 禁用模型 | PATCH /enable=false 后，请求该模型返回 503 |
| M-07 | 启用模型 | PATCH /enable=true 后，请求该模型正常通过 |
| M-08 | 删除模型（无授权） | DELETE 成功，DB 记录删除 |
| M-09 | 删除模型（有活跃授权） | DELETE 返回 400，提示必须先撤销授权 |
| M-10 | 连通性测试 | POST /test 返回 success=true 或 false + latencyMs |

### 1.2 上游鉴权配置

| # | 验收项 | 通过条件 |
|---|---|---|
| M-11 | api_key 类型 | 上游请求带 `Authorization: Bearer {key}` |
| M-12 | none 类型 | 上游请求不带任何鉴权 Header |
| M-13 | SK 存储 | DB 中 `mg_model_credential.secret_key` 为密文（非明文） |

## 3. 凭证管理验收

| # | 验收项 | 通过条件 |
|---|---|---|
| C-01 | 生成 API Key | 响应包含 `apiKey` 明文字段（仅此一次） |
| C-02 | 生成 AK/SK | 响应包含 `accessKey` 和 `secretKey` 明文（仅此一次） |
| C-03 | 查询凭证列表 | 返回中无 apiKey/secretKey 明文，只有末4位 + **** |
| C-04 | 凭证用于鉴权 | 生成的 API Key 可立即用于 /v1/chat/completions |
| C-05 | 禁用凭证 | PATCH /disable 后，该凭证 401，同系统其他凭证不受影响 |
| C-06 | 删除凭证 | DELETE 后凭证立即 401 |
| C-07 | 凭证过期 | 超过 expiresAt 后返回 403（非 401），记录不删除 |
| C-08 | DB 中无明文密钥 | 检查 `mg_app_credential.secret_hash` 为 SHA-256 hash |

## 4. 模型授权验收

|---|---|---|

## 5. 访问控制验收

| # | 验收项 | 通过条件 |
|---|---|---|
| AC-01 | 规则为空不限制 | 无访问规则时任意 IP 可通过 |
| AC-02 | IP 白名单生效 | 添加精确 IP 规则后，其他 IP 返回 403 |
| AC-03 | CIDR 白名单生效 | 添加 10.0.0.0/8，10.x.x.x 通过，192.168.x.x 被拒绝 |
| AC-04 | 删除规则后实时生效 | 删除所有规则后，任意 IP 可访问（规则为空不限制） |
| AC-05 | 缓存失效 | 添加/删除规则后 60s 内生效（Caffeine TTL 60s） |

## 6. 网关鉴权链验收

| # | 验收项 | 通过条件 |
|---|---|---|
| G-01 | 无 Authorization 请求 | 返回 401 |
| G-02 | 无效 API Key | 返回 401 |
| G-03 | 有效 API Key | 请求正常转发至上游 |
| G-04 | AK/SK 签名正确 | 请求正常转发 |
| G-05 | AK/SK 时间戳超时 | 超过 ±5min 返回 401 |
| G-06 | AK/SK 签名错误 | 返回 401 |
| G-07 | 开关优先级 | 系统禁用 → 凭证禁用 → IP 白名单 → 模型授权 → 模型状态，按序执行 |
| G-08 | 熔断触发 | 上游连续失败达阈值后，请求返回 503 |
| G-09 | 流式响应 | stream=true 时，响应为 SSE 格式，不缓冲 |

## 7. 缓存与性能验收

| # | 验收项 | 通过条件 |
|---|---|---|
| P-01 | Caffeine L1 命中 | 同一凭证第二次请求不查 Redis（metrics 可见） |
| P-02 | Redis L2 降级 | Redis 停止后，L1 缓存内的凭证继续放行 |
| P-03 | Redis L2 降级拒绝 | Redis 停止 + L1 过期后，新请求返回 503 |
| P-04 | 模型配置刷新 | 修改上游地址后 30s 内网关使用新地址 |
| P-05 | 凭证主动失效 | 禁用凭证后，下一个请求（无需等 TTL）立即 401 |

## 8. 安全验收

| # | 验收项 | 通过条件 |
|---|---|---|
| S-01 | DB 密钥加密 | `mg_model_credential.secret_key` 不可被直接解读为明文 |
| S-02 | API Key 不可查 | GET /credentials 响应无明文 API Key |
| S-03 | 日志无明文密钥 | 应用日志中搜索不到 "sk-" 开头的完整 Key |
| S-04 | 时序攻击防护 | API Key 比对使用 MessageDigest.isEqual，非 String.equals |
| S-05 | Admin 接口保护 | 无 Token 访问 /admin/** 返回 401 |
| S-06 | Admin IP 白名单 | 非白名单 IP 访问 /admin/** 返回 403 |
| S-07 | Actuator 保护 | /actuator/prometheus 等管理端点需 Admin 鉴权 |
| S-08 | Health 端点公开 | /actuator/health 和 /actuator/info 无需鉴权 |

## 10. 整体冒烟测试

以下测试场景必须端到端全通：

```
1. 创建模型 gpt-4o（api_key 类型，openai 规范）
2. 创建接入系统 crm-service
3. 为 crm-service 生成 API Key
4. 为 crm-service 授权访问 gpt-4o（QPS=5）
5. 使用 API Key 调用 POST /v1/chat/completions，model=gpt-4o
   → 期望：请求转发至上游，返回正常响应
6. 禁用 crm-service 的 gpt-4o 授权
   → 再次调用返回 403
7. 重新启用授权
   → 再次调用正常
8. 禁用 crm-service 系统
   → 调用返回 401（凭证立即失效）
9. 删除 crm-service
   → 级联数据均删除，凭证不可用
```
