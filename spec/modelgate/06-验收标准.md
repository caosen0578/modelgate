## 11.1 通用服务接入验收（2026-08-27 新增）

**服务注册**
- [ ] 服务编码不符合 `^[a-z0-9][a-z0-9-]{1,31}$` 时被拒绝（大写、含斜杠、1 位、以连字符开头各试一次）
- [ ] 同编码重复创建返回"已存在"；**软删后可用同编码重建**
- [ ] 上游地址不以 `http(s)://` 开头被拒；末尾斜杠被自动去掉（存库值无尾斜杠）
- [ ] 编辑时服务编码输入框置灰、无法修改
- [ ] SK 与附加请求头在列表与详情接口中**均不回显明文**，仅返回"是否已配置"
- [ ] 编辑时 SK 留空 = 保持原值；把鉴权类型改成 `none` 才会清空

**转发链路**
- [ ] `POST /svc/{编码}/api/x` 带有效凭证且已授权 → 正确转发到 `{upstream_url}/api/x`
- [ ] 关闭「剥离前缀」后 → 转发到 `{upstream_url}/svc/{编码}/api/x`
- [ ] 请求 `/svc/` 或 `/svc`（无编码）→ 404 `SERVICE_CODE_MISSING`
- [ ] 编码不存在 → 404；服务被禁用 → 503；未授权 → 403；授权过期 → 403
- [ ] **上游收到的请求头里没有调用方的 `Authorization` 与 `X-Mg-*`**，只有该服务配置的上游凭证
- [ ] SSE 服务逐帧透传，不攒批
- [ ] 请求体**原样透传**：上游收到的字节与调用方发出的完全一致（含 chunked 上传）

**配额与隔离**
- [ ] 服务 QPS/日调用量超限返回 429
- [ ] **服务编码与某个 modelId 同名时，两者配额互不影响**（Redis key 带 `svc:` 前缀）
- [ ] 服务无月 Token 配额（授权表无该字段，配额检查不发第三次 Redis 命令）

**审计与报文**
- [ ] 服务调用在 `mg_audit_log` 留下 `traffic_type='service'` + `service_id` 的记录
- [ ] **用量统计不把服务调用算进模型用量**（`selectUsageStats` 带 `traffic_type='model'`）
- [ ] `mg_service.payload_log_enabled` 开启后报文落 `mg_request_payload`，关闭则不落
- [ ] 审计页/报文页按流量类型与服务编码筛选生效

**回归（服务接入不得影响模型流量）**
- [ ] `/v1/**` 全链路行为与接入前完全一致（`TrafficTypeTest` 的逐路径等价断言必须通过）
- [ ] **`/v1`（无尾斜杠）与 `/v1;a=b/...` 仍会被鉴权**，不得因流量分流被跳过

## 12. 整体冒烟测试

以下场景必须端到端全通：

```
1. 创建模型 gpt-4o（api_key 类型，openai 规范）
2. 创建接入系统 crm-service
3. 为 crm-service 生成 API Key
4. 为 crm-service 授权访问 gpt-4o（QPS=5）
5. 使用 API Key 调用 POST /v1/chat/completions（model=gpt-4o）
   → 请求转发至上游，返回正常响应
6. 禁用 crm-service 的 gpt-4o 授权 → 再调返回 403
7. 重新启用授权 → 再调正常
8. 禁用 crm-service 系统 → 调用返回 403（APP_DISABLED，凭证立即失效）
9. 删除 crm-service → 级联逻辑删除，凭证不可用
10. 撤销并重新授权同一 (app, model) → 成功（uk 含 is_del）
```
