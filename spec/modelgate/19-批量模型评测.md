# 批量模型评测

分离管理前端在「报文记录」勾选模型报文，先预检再保存评测集。「模型评测」管理固定版本的样本、后台任务、执行结果、参考答案和人工评分。首期接受包含 messages 的 Chat Completions JSON 报文。

## 样本与任务

评测集保存请求、历史原始响应及正文、模型与来源标识、历史 Token 和完整性标记。快照剔除入站请求头。源报文清理后仍可执行，修改参考答案会发布一个新版本。任务固定评测集版本、目标模型配置、统一参数、并发和超时。统一参数不能替换 messages、input 或模型身份。任务创建时通过适配器预检并保存最终请求，实际执行继续校验最终请求。执行时读取目标模型当前有效凭证。目标模型的连接配置变更后，需复制任务并按当前配置执行。

评测集引用中的历史 Token 按原来的审计关联标记展示；重复 TraceID 的用量显示存疑。每个样本的每次评测结果独立记录，重跑新增尝试。

## 执行

任务与结果保存在四张评测表中。工作进程每秒领取待执行项，领取期间锁住任务，按全实例的任务并发约束执行。每实例默认两个执行槽，定期刷新 45 秒租约。任务取消会标记排队和在途项，工作进程随后取消本地订阅。超过租约的运行项标记为 UNCERTAIN，需显式重跑。迟到响应只能写回仍由本进程持有的 RUNNING 项，无法覆盖取消或过期状态。

执行复用 ProviderRequestPipeline 以及响应适配器，保存最终请求、原始响应、正文、Token、状态及耗时。采用统一响应解码提取正文，留档的原始响应保留上游格式。评测调用直连上游，Token 记录在评测任务中。响应超过配置的留档上限会标记 TRUNCATED 并说明结果不完整。

## 页面

- 评测集支持查看快照、编辑参考答案后发布新版本、创建任务和删除未被使用的版本。
- 任务支持进度与状态查看、复制、取消、选中结果重跑、人工判定及 0–100 分评分。
- 对比支持历史基线或同一评测集版本的其他任务，分别查看请求参数、正文、工具参数、原始响应和参考答案。可只看差异、格式化并排序 JSON。历史入站请求与本次最终上游请求分别标识。
- 导出 CSV 保存指标和评分，JSON Lines 保存每条样本、任务配置与完整结果。

## 部署

1. 存量网关库执行 `sql/upgrade_20261117_model_evaluation.sql`，新库使用更新后的全量脚本。
2. 用户库执行 `28_modelgate_evaluation_perm_increment_20261117.sql`，为评测人员配置菜单、查询、执行、取消、重跑、评分和全文导出权限。报文记录中的应用与个人样本预检和保存分别登记权限。
3. 部署后端和分离管理前端。评测页位于 `/modelgate/evaluation`。

配置项均位于网关应用配置或 Apollo，代码提供默认值。

| 配置 | 默认值 | 含义 |
|---|---:|---|
| modelgate.evaluation.enabled | true | 是否运行后台工作进程 |
| modelgate.evaluation.worker-slots | 2 | 单实例在途执行槽 |
| modelgate.evaluation.poll-ms | 1000 | 领取及心跳间隔毫秒 |
| modelgate.evaluation.max-cases | 200 | 单个评测集样本上限 |
| modelgate.evaluation.max-sample-bytes | 4194304 | 单条样本快照大小上限 |
| modelgate.evaluation.max-dataset-bytes | 67108864 | 单个评测集快照总大小上限 |
| modelgate.evaluation.max-response-bytes | 4194304 | 单次原始响应和解码响应的留档上限 |
| modelgate.evaluation.max-concurrency | 4 | 单个任务允许的并发上限 |

任务并发、单条超时在创建页填写。操作人字段沿用 OperatorProvider，行内接入应使用真实用户上下文实现。样本快照和结果由管理员显式删除，独立于原报文保留期。后续可增加规则自动评分、多次运行的统计汇总和模型自动评分。
