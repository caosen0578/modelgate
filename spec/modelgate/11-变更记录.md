## 1. 统一返回结构改用行内 Result

- **管理后台 Controller**（8 个）返回值由旧 `common.Result`（`code/message`）改为**行内标准** `com.pab.ficc.cus.web.result.Result`（`resultCode`(成功`00000000`)/`resultMessage`/`data`/`requestId`/`requestTime`/`logTraceId`）。成功用 `Result.success(x)`。
- `GlobalExceptionHandler` 同步输出行内 Result（`resultCode/resultMessage`）。
- **网关 Filter 对外业务流量（`/v1/**`）错误响应仍用旧 `common.Result`（`code/message`）不变**——对外契约稳定，两套结构并存、互不影响。
- `admin.html` 前端解析同步改为 `resultCode==='00000000'` / `resultMessage`（`data` 字段名不变）。
- **影响**：`/admin/**` 成功/失败响应 JSON 结构变化，前端已适配。

## 2. 内部规范基础字段 + 逻辑删除 + 自动填充

- 7 张管理表实体新增基础字段：`creater / create_time / updater / update_time / is_del / creater_um / updater_um`；旧 `created_at/updated_at` → `create_time/update_time`。
- `is_del` 标注 `@TableLogic(value="0", delval="1")`：**delete 变为逻辑删除**（UPDATE is_del=1），查询自动过滤已删行。
- 自动填充：`config/AuditFieldMetaObjectHandler`（注册于 `TdsqlMybatisPlusConfig` 的 GlobalConfig）—— insert 填 create_time/update_time/is_del/creater/updater/um，update 填 update_time/updater/updater_um。`creater/updater/um` 取自 `common/OperatorProvider`（默认实现 `DefaultOperatorProvider` 当前返回 null，**待接入行内用户上下文**）。
- **唯一键**：`mg_app_model_auth` 唯一键改为 `(app_id, model_id, is_del)`，支持撤销后重新授权。
- 命名统一（`e2e9c1c`）：`GatewayConfig.updated_by` 并入 `updater`；`AuditLog.created_at` → `create_time`（实体/Mapper SQL/Service 三处一致）。
- **审计表 `mg_audit_log` 不含基础字段**（高频追加表，仅 `create_time`）。
- **⚠️ 已登记风险**：逻辑删除下软删行仍占唯一键——`mg_model.model_id` / `mg_app.app_id` 删除后同名重建会 `Duplicate key`（`mg_gateway_config` 软删后同 key 重存亦主键冲突）。见 [10 §6](./10-部署与运维手册.md)。

## 3. 命名规范：Entity / RequestBO / VO + UrlConstant

- 实体统一 `*Entity` 后缀（`ModelInstanceEntity` 等 8 个），位于 `domain/entity`。
- 前端入参统一 `*RequestBO` 后缀（`CreateModelRequestBO` 等 11 个），`domain/dto/` → `domain/bo/`。
- 出参 `*VO` 后缀（不变）。分页基类 `com.pab.ficc.cus.domain.base.bo.BaseBo` 可选继承。
- **接口路径常量统一收口** `common/UrlConstant`：Controller 类级 `@RequestMapping(UrlConstant.ADMIN_MODELS)`、方法级 `@GetMapping(UrlConstant.DETAIL)`；**禁止散落路径字面量**。URL 值不变，前端不受影响。

## 6. 本地运行支持（local Profile）——⚠️ 合入内网时删除/忽略

> 目的：脱离 Apollo / Venus 数据源 / 内网 Redis 集群，用一个本地 MySQL + 本地 Redis 起服务，通过 `admin.html` 联调。**这些兼容件合入内网时全部删除或忽略。**

- **默认 Profile = local**（双保险，确保本地免带参数即跑）：
  - `application.yml`：`spring.profiles.active: ${SPRING_PROFILES_ACTIVE:local}`
  - `ModelGateApplication.main()`：`setDefaultProperties(spring.profiles.default=local)`
  - **内网各环境用环境变量 `SPRING_PROFILES_ACTIVE=dev/prod` 显式覆盖即可，不受影响。**
- **数据源**：`ServiceConfiguration` 按 bean 级 `@Profile` —— 非 local 用 `VenusDataSourceBean`；local 用 HikariCP 直连 `datasource.local.*`（`localDataSource` bean）。
- **Redis**：`RedisConfig` 按 bean 级 `@Profile` —— 非 local 用 `RedisClusterProvider`；local 用 **jedis 直连本地 Redis**（`redis.local.{host,port,password}`）。
- **Apollo**：`@EnableApolloConfig` 从启动类移到 `apollo/ApolloConfig`（`@Profile("!local")`）；`DynamicConfigHolder` 去掉 Apollo 监听、只留 `@Value` 承接；`bootstrap-local.yml` 关闭 Apollo/Consul bootstrap。
- **logback**：`logback-spring.xml` 的控制台 root 增加 `local` profile（原只有 dev/prod）。
- **配置文件**：`application-local.yml`（数据源 `datasource.local.*` + 本地 Redis + admin token `local-admin-token` + 测试加密密钥 + Apollo 关闭）——**被 `.gitignore` 忽略，不入库**（含本地库密码）。
- pom：加 `com.zaxxer:HikariCP`、`redis.clients:jedis:3.8.0`（均本地用，随桩删除）。
- **启动方式**：`java -jar target/modelgate-1.0.0-SNAPSHOT.jar`（默认 local）或 IDEA 里 Run（建议 Run Config 设 `Active profiles: local`）。
- **⚠️ 打包坑（本轮踩过）**：残留 java 进程会锁定 `target` 下 jar，导致 `mvn package` 的 repackage 静默不覆盖、跑到旧包。**重打包前务必确认旧进程已退出**。
