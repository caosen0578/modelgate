## 3. 过滤器执行顺序（强制，order 值不得随意更改）

```
请求进入
    │
    ▼  order=-200  AdminAuthFilter
       保护 /admin/** 和 /actuator/**，其他路径直接放行
    │
    ▼  order=-190  CredentialAuthFilter
       API Key → SHA256 hash → Caffeine L1 → Redis L2 → DB L3
       AK/SK → 取出 SK → 重算签名 → 比对 → 时间戳防重放(±5min)
       未通过 → 401
    │
    ▼  order=-180  AppAccessControlFilter
       从凭证关联的 app_id 加载访问规则（Caffeine 缓存）
       校验客户端 IP（ip/cidr）或 Origin 域名（domain/domain_wildcard）
       规则为空 → 直接放行（K8s 动态 IP 场景适用）
       未通过 → 403
    │
    ▼  order=-170  ModelAuthFilter
       解析请求体中的 model 字段（从 path 或 body）
       查询 mg_app_model_auth（Caffeine 缓存）
       校验：系统开关 → 授权开关 → 授权是否过期 → 模型是否启用
       未通过 → 403
    │
    ▼  order=-160  QuotaFilter
       检查 QPS 限制（Redis Lua 滑动窗口）
       检查日调用量限制（Redis，TTL 到当天 24:00）
       检查月 Token 配额（Redis，TTL 到月末）
       超限 → 429；Redis 不可用时 fail-open
    │
    ▼  order=-155  BodyParseFilter
       读取请求体字节，缓存到 exchange attribute（mg.bodyBytes）
       提取 JSON 中的 model 字段，写入 mg.modelId
       重建请求流供后续 Filter 正常读取
    │
    ▼  order=-150  TraceFilter
       生成 traceId（UUID 前16位），写入 MDC 和响应头 X-Trace-Id
       写入 X-Mg-App、X-Mg-Model 响应头
       doFinally：调用 AuditService.log() 写审计（appId/modelId/credType/ip/latencyMs/httpStatus）
    │
    ▼  order=-140  ModelRouteFilter
       加载 ModelInstance + ModelCredential（Caffeine 缓存 30s）
       调用对应 ProviderAdapter 转换请求体和路径
       注入上游鉴权 Header
       设置 GATEWAY_REQUEST_URL_ATTR
    │
    ▼  order=-50   CircuitBreakerFilter
       Resilience4j，熔断器按 model_id 独立实例
    │
    ▼  Spring Cloud Gateway 路由转发
    │
    ▼  doFinally   TraceFilter → AuditService.log()（DB 队列 + Kafka 双写）
```

## 4. 缓存策略（强制执行，不得自行发明）

| 缓存内容 | L1 Caffeine TTL | L2 Redis | 主动失效时机 |
|---|---|---|---|
| App 凭证信息（含权限） | 60s | 永久 | 凭证/系统状态变更时 |
| 模型配置（上游地址等） | 30s | 不存 Redis | 定时刷新（30s调度） |
| 访问规则 | 60s | 不存 Redis | 规则变更时 |
| 模型授权 | 60s | 永久 | 授权变更时 |

**降级规则：** Redis 故障时，已在 L1 缓存中的凭证继续放行；新请求（L1 miss）直接拒绝（不穿透到 DB 避免雪崩）。

## 5. 数据库操作约束

- **必须**使用 MyBatis Plus `BaseMapper` + `LambdaQueryWrapper`，查询逻辑在 Service 层或 Mapper 接口方法中
- **禁止**编写 XML Mapper 文件（所有查询用 Lambda API 表达）
- **禁止**使用原生 `JdbcTemplate` / `NamedParameterJdbcTemplate`
- **禁止**在 Service 层手写 SQL 字符串
- **必须**启用 `map-underscore-to-camel-case: true`（下划线自动转驼峰，无需 `@TableField`）
- **必须**使用 `@TableName` 标注实体对应表名，`@TableId(type=IdType.AUTO)` 标注主键

## 6. 安全约束

| 规则 | 实现要求 |
|---|---|
| 密钥加密存储 | 使用 `CryptoService`（AES-256-GCM），密钥从环境变量读取 |
| API Key 存储 | DB 中存 `SHA-256(api_key)`，用于校验；原文仅创建时响应 |
| AK/SK 存储 | AK 明文，SK 加密存储 |
| 字符串比较 | API Key 比对必须使用常量时间算法（`MessageDigest.isEqual`）|
| 日志脱敏 | 日志中禁止打印完整的 API Key / SK |

---

## 7. WebFlux 约束（Spring Cloud Gateway 是响应式框架）

- **所有 Filter** 必须返回 `Mono<Void>`，不得阻塞线程
- **Controller 中的 DB 操作** 必须切换到 `Schedulers.boundedElastic()` 线程池
- **禁止**在 GlobalFilter 中调用同步 JDBC，必须包裹在 `Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())` 中
- **禁止**在 Filter 内直接使用 `Thread.sleep()` 或其他阻塞调用

## 8. 审计日志优化设计

### 8.1 写入优化（in-memory 队列 + 批量 INSERT）

原单条 INSERT 在 30 QPS 下每天产生 ~260 万次写入，改为：

1. `AuditService.log()` 将日志 offer 到 `LinkedBlockingQueue`（容量 200,000），立即返回
2. `@Scheduled(fixedDelay=2000)` 定时从队列取最多 5,000 条，一次 `batchInsert` 写入
3. 队列满时 `offer()` 返回 false，丢弃并打 WARN 日志（fail-open，不影响主链路）
4. Kafka 发送保持每条即时发送，不走队列缓冲

配置项（`application.yml`）：

```yaml
modelgate:
  audit:
    topic: modelgate-audit-log
    enabled: true
    db-write: true
    buffer-size: 200000
    flush-interval-ms: 2000
    retention-days: 90
    cleanup-cron: "0 0 2 * * ?"
```

### 8.2 清理策略（AuditCleanupService）

- 默认保留 90 天，每天凌晨 2 点触发
- 批量 DELETE：每批 10,000 行 + 200ms sleep，避免大事务锁表
- 循环直到本批删除量 < 批次大小为止

```sql
-- 执行模板（循环）
DELETE FROM mg_audit_log WHERE created_at < #{cutoff} LIMIT 10000;
```

### 8.3 caller_app_id 字段

`mg_audit_log` 新增 `caller_app_id VARCHAR(64)`，记录请求方通过 `X-App-Id` Header 声明的系统标识，用于跨系统调用链追踪（非鉴权字段，不做强验证）。
