## 3. 过滤器执行顺序（强制，order 值不得随意更改）

```
请求进入
    ▼ [WebFilter] TraceWebFilter  生成 traceId→Reactor Context（自动同步 MDC）+ X-Trace-Id 响应头
    │                             作用于**全部**请求，含 /modelgate/** 与静态资源
    ▼      （以下为 GlobalFilter，只对匹配路由的 /v1/** 生效；
            管理面 /modelgate/** 与 /actuator/** 不匹配任何路由，根本不进本链路）
    ▼ -200 TraceFilter            doFinally→AuditService.log()；必须第一个，否则被拒请求不进审计
    ▼ -190 CredentialAuthFilter   Bearer→SHA256→L1→DB；AKSK→时间戳±5min→HMAC 验签；未过 401
    ▼ -180 AppAccessControlFilter ip|cidr|domain|domain_wildcard；规则为空放行；未过 403
    ▼ -175 BodyParseFilter        缓存 body 字节→mg.bodyBytes；提取 model→mg.modelId；重建请求流
    ▼ -170 ModelAuthFilter        系统开关→授权开关→授权过期→模型启用；未过 403
    ▼ -160 QuotaFilter            QPS(INCR 秒级滑窗)→日调用→月 Token；超限 429；Redis 故障 fail-open
    ▼ -140 ModelRouteFilter       加载模型+凭证(缓存30s)→Adapter 转换→注入上游鉴权→覆盖路由
    ▼ -50  CircuitBreakerFilter   Resilience4j，按 model_id 独立实例
    ▼ Spring Cloud Gateway 转发上游
    ▼ doFinally TraceFilter → AuditService.log()（**全量**：成功与被拒请求都记，被拒时 app_id 为空）
```

## 4. 缓存策略（强制执行，不得自行发明）

| 缓存内容 | Caffeine TTL | miss 数据源 | 主动失效时机 |
|---|---|---|---|
| App 凭证信息 | 60s | MySQL | 凭证/系统状态变更时 |
| 接入系统信息 | 60s | MySQL | 系统增删改启禁时 |
| 模型配置（上游地址等） | 30s | MySQL | 模型增删改启禁时 |
| 上游模型凭证（已解密） | 30s | MySQL | 模型凭证变更时 |
| 访问规则 | 60s | MySQL | 规则变更时 |
| 模型授权 | 60s | MySQL | 授权变更、模型改名/删除时 |

**真实读取与降级规则**：上述缓存均使用 Caffeine 原子加载合并同 key 的并发 miss，直接回源 MySQL；
Redis 不充当 L2，故 Redis 故障不会决定凭证查询放行/拒绝，只会令 QuotaFilter 按既定策略 fail-open。
主动失效当前只作用于处理管理请求的 JVM，其他实例按 30/60 秒 TTL 收敛；禁止把 Redis `DEL`
描述成跨实例 Caffeine 通知，除非后续确实实现并验证 Pub/Sub 等广播机制。

## 5. 数据库操作约束

- **必须** MyBatis Plus `BaseMapper` + `LambdaQueryWrapper`；**禁止** XML Mapper、`JdbcTemplate`、Service 层手写 SQL
- **必须** `map-underscore-to-camel-case: true`；`@TableName` + `@TableId(type=AUTO)`
- 组合写操作必须使用绑定 `tdsqlDataSource` 的 `tdsqlTransactionManager`；项目排除了事务管理器自动配置，禁止只加 `@Transactional` 而不提供对应 Bean
- **基础字段**（内部规范，7 张管理表强制；`mg_audit_log` 除外）：
  `creater / create_time / updater / update_time / is_del / creater_um / updater_um`

### 5.1 基础字段自动填充与逻辑删除

- `AuditFieldMetaObjectHandler`（注册于 `TdsqlMybatisPlusConfig` 的 GlobalConfig）：
  - insert 填充：create_time / update_time / is_del('0') / creater / updater / creater_um / updater_um
  - update 填充：update_time / updater / updater_um
  - 操作人来自 `OperatorProvider`（当前占位 null，接入行内用户上下文后以 `@Primary` 实现覆盖）
- `is_del` 标注 `@TableLogic(value="0", delval="1")`：delete 变 UPDATE，查询自动过滤已删行
- **唯一键规则**：软删行仍占用唯一键，故**所有业务唯一键一律纳入 `is_del`**——`mg_model`/`mg_model_credential` 的 `uk_model_id`、`mg_app` 的 `uk_app_id`、`mg_app_model_auth` 的 `uk_app_model` 均已包含。新增管理表遵循同一规则
- **`mg_gateway_config` 不做逻辑删除**：无 `is_del` 列与 `@TableLogic`，`deleteById` 为物理 DELETE。`config_key` 即主键，软删后同 key 无法重建，且配置非业务数据无留痕需求

## 7. WebFlux 约束（响应式框架）

- 所有 Filter 返回 `Mono<Void>`，不得阻塞
- Controller / Filter 中 DB 操作必须 `Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())`
- 禁止 `Thread.sleep()`、`.block()` 等阻塞调用
- MDC 不跨 reactor 线程传播：行内 Result 的链路字段可能为空，以响应头 `X-Trace-Id` 为准

## 8. 审计日志设计（内存队列 + 批量写 MySQL）

1. `AuditService.log()`（TraceFilter doFinally 调用）将记录 offer 进 `LinkedBlockingQueue`（容量 200,000），立即返回
2. `@Scheduled(fixedDelay=2000)` 每批 `drainTo` 最多 5,000 条，一次 `batchInsert`
3. 队列满 → 丢弃 + WARN（含进程内累计丢弃数，fail-open，不影响主链路）
4. 批量失败 → 仅 WARN，本批丢失，不重试
5. 月度 Token 累计：批内按 (appId, modelId) 分组汇总后一次 INCRBY Redis（无论 DB 开关均执行）

**可观测**：队列满时打 WARN 并带累计丢弃数（Prometheus 指标已移除，见 [10 §5](./10-部署与运维手册.md)）。

配置（`application.yml`；apollo-client 已移除，改后需重启）：

```yaml
modelgate:
  audit:
    enabled: true
    db-write: true
    buffer-size: 200000
    flush-interval-ms: 2000
    retention-days: 90
    cleanup-cron: "0 0 2 * * ?"
```

**清理**（AuditCleanupService）：默认保留 90 天，每天 02:00 触发；每批 `DELETE ... LIMIT 10000` + 200ms sleep，循环至删完，防大事务锁表。

### 8.1 caller_app_id 字段

`mg_audit_log.caller_app_id VARCHAR(64)`：请求方经 `X-App-Id` Header 声明的系统标识，用于跨系统调用链追踪（非鉴权字段，不做强验证）。
