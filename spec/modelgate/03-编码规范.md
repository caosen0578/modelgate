# Spec Me2AI · 03 · 编码规范

> **文档性质**：人工编写，AI 严格遵守，不得以"代码更整洁"为由绕过规范

---

## 1. 命名规范（强制）

### 1.1 类命名

| 类型 | 命名规则 | 示例 |
|---|---|---|
| Filter | `{功能}Filter` | `CredentialAuthFilter` |
| Controller | `{资源}Controller` | `ModelController` |
| Service | `{资源}Service` | `CredentialService` |
| DAO | `{资源}Dao` | `AppCredentialDao` |
| Entity | 与表名对应，去下划线转 PascalCase | `AppModelAuth` |
| Adapter | `{提供商}Adapter` | `AnthropicAdapter` |
| Exception | `BusinessException`（统一使用，不得新建子类） | — |

### 1.2 方法命名

| 操作 | 前缀 | 示例 |
|---|---|---|
| 查询单条 | `findBy{字段}` | `findByAppId` |
| 查询列表 | `listBy{字段}` | `listByAppId` |
| 插入 | `insert` | `insert(AppInfo app)` |
| 更新 | `update` | `update(AppInfo app)` |
| 删除 | `deleteById` | `deleteById(Long id)` |
| 启用/禁用 | `enable` / `disable` | `enableApp(Long appId)` |
| 缓存失效 | `evict{资源}Cache` | `evictCredentialCache(String key)` |

### 1.3 常量命名

- 全大写下划线分隔：`MAX_RETRY_COUNT`、`CACHE_KEY_PREFIX`
- Filter order 常量定义在各自 Filter 类内，不得定义在公共常量类中

### 1.4 数据库字段 → Java 字段映射

- 下划线转驼峰，**手工在 RowMapper 中映射，禁止依赖框架自动转换**
- 示例：`app_id` → `appId`，`created_at` → `createdAt`

## 2. Mapper 层规范（强制）

### 2.1 Mapper 接口规范

- 每张业务表对应一个 `@Mapper` 接口，继承 `BaseMapper<Entity>`
- 命名：`{实体名}Mapper`，放在 `mapper/` 包下
- 简单 CRUD 直接调用 `BaseMapper` 提供的方法，**禁止重复实现**
- 复杂查询使用 `LambdaQueryWrapper`，在 Service 层构造后传入

```java
// 正确：Mapper 接口定义
@Mapper
public interface AppMapper extends BaseMapper<AppInfo> {
    // 无需任何方法，BaseMapper 已提供 insert/selectById/updateById/deleteById/selectList 等
}

// 正确：Service 中使用 LambdaQueryWrapper
Optional<AppInfo> findByAppId(String appId) {
    return Optional.ofNullable(appMapper.selectOne(
        new LambdaQueryWrapper<AppInfo>().eq(AppInfo::getAppId, appId)
    ));
}
```

```java
// 禁止：编写 XML Mapper 文件
// 禁止：在 Mapper 接口中写 @Select("SELECT * FROM ...")
// 禁止：手写 RowMapper 或 ResultSetExtractor
```

### 2.2 Entity 注解规范

```java
@Data
@TableName("mg_app")
public class AppInfo {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String appId;      // 自动映射 app_id（下划线转驼峰）
    private String appName;    // 自动映射 app_name
    // ...
}
```

### 2.3 批量操作

- 使用 MyBatis Plus `IService.saveBatch()` 或 `baseMapper.insert()` 循环（数据量小时）
- 大批量使用 `IService.saveBatch(list, batchSize)`

## 3. Service 层规范（强制）

### 3.1 职责边界

- Service 只调用 DAO 和其他 Service，**禁止在 Service 层写 SQL**
- 缓存操作（Caffeine + Redis）统一在 Service 层，**禁止在 Controller 层直接操作缓存**
- 业务校验（如"存在活跃授权时禁止删除模型"）在 Service 层抛出 `BusinessException`

### 3.2 缓存操作模板

```java
// 写操作：先写 DB，再主动失效缓存（不主动写缓存）
public void updateModel(ModelInstance model) {
    modelDao.update(model);
    cacheManager.evictModelCache(model.getModelId());
}

// 读操作：Caffeine → Redis → DB 三级
public AppCredential getCredential(String apiKeyHash) {
    // 实现见 GatewayCacheManager
}
```

### 3.3 WebFlux 线程切换

```java
// Controller 中，DB 操作必须切换到 boundedElastic
public Mono<Result<AppInfo>> getApp(String appId) {
    return Mono.fromCallable(() -> appService.findByAppId(appId))
               .subscribeOn(Schedulers.boundedElastic())
               .map(Result::ok);
}

// Filter 中，DB 操作必须包裹
return Mono.fromCallable(() -> credentialService.findByHash(hash))
           .subscribeOn(Schedulers.boundedElastic())
           .flatMap(cred -> { ... });
```

## 4. Filter 层规范（强制）

### 4.1 错误响应格式

- 所有 Filter 拒绝请求时，必须返回 `application/json`，格式为 `Result<Void>`
- **禁止** 直接返回纯文本或 HTML

```java
// 正确
private Mono<Void> reject(ServerWebExchange exchange, int statusCode, ErrorCode errorCode) {
    var response = exchange.getResponse();
    response.setStatusCode(HttpStatus.valueOf(statusCode));
    response.getHeaders().setContentType(MediaType.APPLICATION_JSON);
    var body = Result.fail(errorCode);
    var bytes = JSON.toJSONBytes(body);
    return response.writeWith(Mono.just(response.bufferFactory().wrap(bytes)));
}
```

### 4.2 请求体读取

- 在 Filter 中读取请求体后，**必须** 重新设置 `ServerRequest`，防止后续 Filter 无法读取
- 使用 `exchange.mutate().request(mutatedRequest).build()` 传递修改后的 exchange

### 4.3 order 值

- 每个 Filter 的 order 值在类顶部以常量定义：`private static final int ORDER = -190;`
- 实现 `Ordered` 接口，`getOrder()` 返回该常量

## 5. Controller 层规范（强制）

### 5.1 返回类型

- **所有** Controller 方法必须返回 `Mono<Result<T>>` 或 `Mono<Result<List<T>>>`
- 禁止返回裸 `T` 或 `ResponseEntity<T>`

### 5.2 路径规范

| 资源 | 路径前缀 |
|---|---|
| 模型管理 | `/admin/models` |
| 接入系统管理 | `/admin/apps` |
| 凭证管理 | `/admin/apps/{appId}/credentials` |
| 模型授权 | `/admin/apps/{appId}/auth` |
| 访问控制 | `/admin/apps/{appId}/access` |
| 网关配置 | `/admin/config` |

### 5.3 HTTP 方法语义

| 操作 | 方法 |
|---|---|
| 查询列表 | GET |
| 查询单条 | GET `/{id}` |
| 创建 | POST |
| 全量更新 | PUT `/{id}` |
| 部分更新（状态开关）| PATCH `/{id}/enable` 或 `/disable` |
| 删除 | DELETE `/{id}` |

## 6. 异常处理规范（强制）

### 6.1 统一异常

- 业务异常统一使用 `BusinessException(ErrorCode errorCode)`
- `GlobalExceptionHandler` 捕获并转换，**不得在 Controller 中 try-catch**

### 6.2 ErrorCode 定义

- 新增错误码只能追加到 `ErrorCode.java`，**禁止** 在 Filter/Controller 中硬编码状态码数字
- ErrorCode 格式：`NAME(httpStatus, bizCode, message)`

## 7. 日志规范（强制）

### 7.1 日志级别

| 场景 | 级别 |
|---|---|
| 正常业务流程 | DEBUG（生产环境关闭）|
| 业务拒绝（401/403/429）| INFO |
| 预期外异常 | WARN |
| 系统级错误 | ERROR |

### 7.2 禁止内容

- **禁止** 日志中打印完整 API Key、SK、密码
- API Key 日志中只能打印末 4 位：`key.substring(key.length() - 4)`
- TraceId 必须出现在所有业务日志的 MDC 中

### 7.3 Logger 声明

```java
// 正确：使用 Lombok @Slf4j 或手动声明
private static final Logger log = LoggerFactory.getLogger(CredentialAuthFilter.class);

// 禁止：System.out.println
System.out.println("debug info"); // 禁止
```

---

## 8. 实体类规范（强制）

- Entity 类无任何框架注解（无 `@Entity`、`@Table`、`@Column`）
- 所有字段必须有 getter/setter（使用 Lombok `@Data` 或手动编写）
- **禁止** 在 Entity 中实现业务逻辑
- 时间字段类型：`LocalDateTime`（禁止使用 `java.util.Date`）
