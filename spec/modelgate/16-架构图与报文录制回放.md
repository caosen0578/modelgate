## 2. 已纠正的旧图内容

1. 部署文根统一为 `/modelgate`；SLB 外部挂载路径与应用文根是两层不同的路径，不可重复拼接。
2. 实例监听优先读取 `PORT_NO`，未设置/空白时使用配置中的 `server.port`，不写死为 8080。
3. 同时表示模型 `/v1/**` 和通用 HTTP/SSE `/svc/{服务编码}/**` 两类业务流量。
4. 管理 API 与静态资源由行内逐接口鉴权/网络入口保护，不经过业务 GlobalFilter 链，也不是本进程自带管理员认证。
5. TraceFilter 为 -200，补齐 BodyParseFilter、ServiceAuthFilter、QuotaFilter、PayloadCaptureFilter 及服务路由分支。
6. ProviderAdapter V2 表示统一请求管线、原生/OpenAI 响应模式及响应侧转换，不只是一层参数转换。
7. 当前模型熔断器共用 `modelUpstream`；服务按 `svc:{serviceId}` 隔离，不能画成模型也已逐实例隔离。
8. 缓存读取为实例内 Caffeine → 数据库；Redis 用于配额，无跨实例 Caffeine 失效广播，无已接入的凭证 L2。

## 3. 报文录制的真实链路

响应：上游 → 模型响应适配（仅模型）→ PayloadCaptureFilter 旁路复制 → 客户端。

收尾：TraceFilter.doFinally → PayloadService.submit → 有界内存队列 → 定时消费解析/序列化 → RequestPayloadMapper 批量写 `mg_request_payload`。

- 模型请求的原始 POST JSON 由 BodyParseFilter 缓存；服务链路不读取请求 body，所以服务正文通常未留存。
- 响应采集的是客户端侧响应形态；模型响应可能已转换为 OpenAI 格式，不是上游线级报文镜像。
- 录制总开关为 `modelgate.payload-log.enabled`；模型另有 `mg_app_model_auth.payload_log_enabled`，服务另有 `mg_service.payload_log_enabled`。
- **非流式服务的现有例外**：PayloadCaptureFilter 对非流式响应先选择 FULL；TraceFilter 服务分支仅凭 FULL 模式决定提交，没有再检查服务开关。因此全局开启时，服务自身关闭录制仍可能留下非流式报文。这是代码现状，图中已标明，本次不修改业务行为。
- FULL 模式默认保护阈值 64 MiB，按块判断；达到后停止后续采集而不停止转发。非流式响应即使不录制，也可能 FULL 采集用于 usage。
- SSE 未开启留档时为 TAIL 模式，仅保存尾部 64 KiB 用于 usage；尾部不能当作完整报文落库。
- 默认定时消费间隔 2 秒、批大小 200；这些是代码默认值，实际配置可通过 `/modelgate/payload/meta` 等管理手段核对。
- 失败批次进入 PendingWriteBuffer，采用退避重试、拆批与坏记录隔离；缓存有上限，异常退出仍可能丢失数据，不是可靠消息队列。
- `mg_audit_log` 是独立审计追加表，通过 traceId 与报文关联；鉴权失败也会尝试记审计，但未必有报文，一对一或事务强一致不成立。
- 全部入站请求头可能包含 Authorization/Cookie/Token，正文含业务信息，当前没有脱敏；需要限制查询与数据库权限。

## 4. 回放的真实链路与限制

管理前端 → 外部逐接口鉴权 → `POST /modelgate/payload/replay?id=…` → PayloadController 查历史 → 当前模型/服务配置与凭证 → ConnectivityService 使用 WebClient 直连上游 → 聚合结果返回页面。

- 不是返回历史响应的 mock，也不恢复历史 SSE 时间间隔。浏览器得到 `ConnectivityTestVO` 聚合结果，而不是实时 SSE。
- 跳过调用方鉴权、来源规则、资源授权、配额与业务熔断链；不新增业务审计/报文，不扣调用方网关额度。管理入口权限与回放 WARN 日志仍存在。
- 使用当前上游配置和凭证，不是历史配置快照；历史入站 Header 不自动注入。依赖原自定义 Header/Cookie/签名的场景不能保证等价复现。
- 请求体优先取手工覆盖值，再取历史正文；两者为空时 Controller 拒绝回放。该校验也作用于原本不带 body 的 GET/HEAD，页面不能承诺任意请求均可一键重发。
- 服务方法/路径优先取覆盖值再取历史值，底层必要时回落到当前服务探测配置；GET/HEAD 不发送正文。
- 服务默认去掉历史文根与 `/svc/{服务编码}` 前缀；`stripPrefix=false`、历史路径缺失/截断等情况需手工核对 path。
- 服务回放 `success` 使用连通性口径，HTTP 4xx 也可能为 true；需要同时核对 httpStatus 与响应正文，不等于业务成功。
- 管理回放有独立等待超时与响应回传上限，不改变在线业务超时。模型走 chat 超时策略，服务回放等待上限为 120 秒，均以相应实现为准。
- 真实调用上游会消耗模型 Token，写请求可能产生重复数据或外部动作，无自动幂等保障。

上述能力边界仅记录现状，本次没有调整报文采集、回放、鉴权或超时业务代码。
