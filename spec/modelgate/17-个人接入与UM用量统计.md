# 模型网关 · 个人接入与 UM 用量统计

## 1. 目标与范围

在「模型网关」下增加与「接入系统」平级的「个人接入」，由管理员为有独立模型使用需求的老师开通。沿用接入系统页面的列表、详情、模型授权、凭证管理、接入示例交互，另加 Token 用量。管理员最终交付网关模型接口、授权的 `model` 和个人 Bearer API Key。老师不需要配置内部 appId、UM 请求头，也不接触上游密钥。

首期仅开放已授权的模型业务流量。不开通通用 `/svc/**`，不新增登录、审批、自助发 Key、聊天页面、跨模型硬预算、人员目录接口或报文留档功能。录入者先核对老师的真实 UM 与姓名；本功能不自动同步人事系统。

## 2. 录入、数据表与编号

| 数据 | 位置与规则 |
| --- | --- |
| 接入主体 | 扩展现有 `mg_app`，**不新建账户表**。新增 `subject_type VARCHAR(16) NOT NULL DEFAULT 'SYSTEM'`、`person_um VARCHAR(64) NULL` 和 `person_um` 唯一索引。现有系统不迁移、不改编号，UM 为 NULL。个人类型固定 `PERSONAL`。 |
| 个人编号 | 后端生成 `P_` + 32 位小写十六进制 UUID（无连字符），例如 `P_8fd619d72b854e599b894aa065e1f6ba`，**34 字符**，小于现有 `app_id VARCHAR(64)`。`P_` 命名空间仅供个人新增；系统新增拒绝此前缀（不区分大小写），保留其他既有 ID 契约，纯数字 ID 按字符串处理。数据库唯一键兜底；撞号则重试，不重用历史编号。主体类型以字段为准，不按前缀重分类存量。 |
| UM / 姓名 | UM 去首尾空白后转大写，仅允许字母、数字、`.`、`_`、`-`，1–64 字符且首字符为字母或数字；同一规范化 UM 只能开通一次。姓名必填（最多 64 字符），备注可选（最多 512 字符）。绑定后 UM 不可修改或转让；停用而非删除，重新启用与换 Key 不更换编号。UM 改号/复用需另定归属迁移方案。 |
| 兼容字段 | 个人姓名保存于 `mg_app.app_name` 和 `owner`，`system_name` 固定为「个人接入」，`sys_code` 为内部标记 `PERSONAL`，`app_code` 与内部编号相同。不修改原 NOT NULL 约束。个人接口/页面不返回这些技术字段或内部 appId。 |
| 个人凭证 | `mg_app_credential`。个人 Key 是 `mgp_` + 安全随机 hex。SHA-256 用于鉴权，AES-256-GCM 密文供授权管理员找回，列表仅显示末 4 位和可找回状态。早期仅存哈希的 Key 需换发。默认有效期 90 天，可指定未来日期。轮换时先发新 Key 验证，再撤销旧 Key。 |
| 模型授权 | `mg_app_model_auth`。按个人 × 已登记模型单独设置授权、QPS、日请求量、月 Token 和有效期，0 表示不限；默认建议值 2 QPS、日 200 次、月 100000 Token。新增授权启用；编辑不隐式恢复停用授权；取消权限用停用，以便恢复且保留历史。个人授权不打开报文留档。 |
| 用量事实 | 继续用 `mg_audit_log`；不增加审计写入字段，不新建计数器。个人查询先以 UM 锁定归属，再按内部 appId 取审计记录，按 UM 和模型输出。Redis 配额与审计统计不是同一口径。 |

## 3. 管理流程与页面

1. 管理员打开「模型网关 → 个人接入」，按 UM/姓名搜索，录入 UM、姓名、备注；重复 UM 提示查看原账户。
2. 在详情配置模型授权和有效期。可编辑姓名/备注、启停个人账户；启停不删除历史用量。
3. 在凭证页创建 Key，复制明文后通过行内安全渠道交付。获 `c900225015` 权限的管理员可单独查看同一 UM 下仍有效且有密文的 Key。关闭弹窗即清除页面明文，示例默认使用占位符。撤销动作仅作用于该 UM 下的指定 Key。
4. 用量页按当前 UM、日期范围查询，展示请求数、输入、输出、合计、上游报告与估算 Token，以及按模型拆分。未提供统计区间时查询最近 30 个自然日；范围最多 90 天，结束日含当天，按网关运行环境日期计算。无记录展示 0；不存在的 UM 不回退为全量。历史共享系统 Key 无法追溯到个人。审计队列异步入库，受保留期和原有落库机制约束，不是实时计费账本。

正式前端 `D:\code\static-framework\src\modules\modelgate` 新增路由、菜单、权限码和页面；后端仓库内置 `admin.html` 同步功能。沿用 `PageVo`、现有文根 `/modelgate`、`modelgateHttp` 和管理面的逐接口鉴权。新增菜单、读写、发 Key、撤销、授权和统计权限；外部入口需按接口登记，前端隐藏按钮不能替代鉴权。管理员有个人管理权限不等于拥有系统管理权限，反之亦然。

## 4. 接口契约

管理菜单展示为「接入用户」，路径与原菜单编码保留。新增页复用 user 服务的 `GET /api/user/cms-user/org` 与 `POST /api/user/cms-user/resolve-org`。失焦查询本地 `cms_user`，显式查询在本地未命中时由 user 调用 CMS 并写回 CMS 快照。新增确认后只写 ModelGate 个人资料。内置页要求同域 SLB 能访问 `/api/user/**`。新增查询使用已有管理入口的逐接口权限。

### 个人 Key 来源白名单

在「接入用户 → 详情 → 访问控制」按 UM 配置固定出口 IP、CIDR、精确域名或单级通配域名。规则复用 `mg_access_rule`，覆盖该用户的所有 Key。两类白名单都为空时不限制来源。配置 IP 规则后，候选 IP 须匹配任一 IP 或 CIDR。配置域名后，还须匹配任一域名规则，只有域名规则时拒绝调用。域名查验使用 `Origin` 或 `Referer` 的主机。来源不匹配返回 HTTP 403。规则更新清理处理节点的缓存，其他实例最多 60 秒后加载新规则。

直连时只用 TCP 对端地址。通过 SLB / Ingress 时，在 ModelGate 启动配置的 `modelgate.personal-access.trusted-proxies` 或环境变量 `MODELGATE_PERSONAL_ACCESS_TRUSTED_PROXIES` 中填写真实代理对端 IP / CIDR 列表。各可信代理需清理外来 `X-Forwarded-For` 或在右侧追加真实对端。网关从右向左跳过已登记的平台代理，取第一个非代理地址，可信代理缺少有效转发来源时白名单校验拒绝。代理网段应仅包含代理。上线从办公出口与另一环境各发一次真实模型调用，确认出口 IP 有区分。共用同一出口的调用方无法由 IP 白名单区分。

用户库执行 `22_modelgate_personal_source_rules_perm_increment_20261115.sql`，给管理员分配 `c900225021` 查询、`c900225022` 新增及 `c900225023` 删除权限。

批量导入使用 UTF-8 CSV 模板 `UM,姓名`，每次最多 100 行。已有 UM 跳过，按行反馈。导入直接使用文件里的人员资料，适用于已核对的名单，权限单独授予。导入不触发 CMS 查询、凭证签发或模型授权。

批量授权从列表勾选用户并搜索多选模型，显示组合数，以同一套配额和有效期新增缺失的授权。每次最多 100 个用户与模型组合、最多 30 个模型。已有授权（含停用或过期）保留原样，停用或已不存在的用户跳过。结果按 UM 与模型返回新增、跳过或失败。重新提交相同组合会跳过已写入的授权。

下列路径均在 `/modelgate/personal-access` 下，Controller 不拼公共文根。所有个人对象以 `um` 定位，不接受客户端传入内部 `appId` 作为操作目标。保留 `Result` 包装、`PageVo` 分页、独立读写路径，密钥返回禁缓存。

| 方法、子路径 | 入参和行为 |
| --- | --- |
| `GET /meta` | 返回 `enabled`，用于个人功能开关提示。 |
| `GET /page` | `pageIndex,pageSize,keyword,enabled`，列出个人 UM、姓名、状态、备注和时间。 |
| `GET /detail` | `um`，查看个人信息。 |
| `POST /create` | `um,name,remark`，仅新建个人，禁止重复。 |
| `POST /import` | `users`，每项含 `um,name,remark`，仅新增个人用户。 |
| `PUT /update` | `um,name,remark`，只修改资料，不改变账户归属或状态。 |
| `PATCH /toggle` | `um,enabled`，启用/停用个人。 |
| `GET /credentials/list` | `um`，返回凭证元数据，不返回明文和哈希。 |
| `POST /credentials/create` | `um,credName,expiresAt`，签发 Key 并返回 `apiKey,id,expiresAt`。 |
| `GET /credentials/secret` | `um,id`，校验归属、个人状态和 Key 有效期后返回单条明文。响应禁止缓存。 |
| `DELETE /credentials/revoke` | `um,id`，校验凭证归属后撤销。 |
| `GET /auth/models` | `pageIndex,pageSize,keyword`，只查可授权的已启用模型标识、名称、类型。 |
| `GET /auth/list` | `um`，返回该人授权模型、用量配置、状态和有效期，不返回 appId。 |
| `PUT /auth/save` | `um,modelId,qpsLimit,dailyLimit,monthlyTokens,expiresAt`，新增或更新一条授权。 |
| `POST /auth/batch` | `ums,modelIds,qpsLimit,dailyLimit,monthlyTokens,expiresAt`，批量新增授权并返回逐组合结果。 |
| `PATCH /auth/toggle` | `um,modelId,enabled`，启停单条授权。 |
| `GET /usage` | `um,start,end`，返回所选个人和日期区间的用量汇总及按模型拆分。 |

## 5. 兼容、安全和发布顺序

个人接入菜单、操作权限及 14 个接口 URL 由 user 项目发布。在 user 库执行 [17 权限增量](D:/code/user/user-server/src/main/resources/db/codebuddy-platform/17_modelgate_personal_access_perm_increment_20261112.sql) 后给指定 96008 角色授权。查询个人接入时一并授予开关和详情 URL，查询模型授权时一并授予模型选项 URL。ModelGate 库执行自身的结构增量。

明文查看由 [18 权限增量](D:/code/user/user-server/src/main/resources/db/codebuddy-platform/18_modelgate_personal_key_reveal_perm_increment_20261113.sql) 单独登记。发布前确认 `modelgate.crypto.key` 与现有加密凭证使用的主密钥一致。生产明文查看走 HTTPS 管理入口，按接口授权并记录操作人，凭证请求和响应明文须排除在入口日志和报文留档之外。

- 个人接口只接受个人 UM；现有系统资料、凭证（含明文查看）、模型/服务授权与来源规则接口拒绝个人 appId。系统列表、系统授权反查及旧系统审计/统计不混入个人；原来没有 appId 的失败记录、已删除系统的历史审计仍可查。
- 个人业务调用用鉴权结果确定归属，不相信来访 UM/应用 ID Header。使用已有缓存，不新增人员查询；只允许启用且有效的个人 Bearer Key、已授权模型。个人请求若授权前没有解析出有效模型，不允许路由补解析后绕过授权。业务路由、适配器、SSE、超时和系统鉴权契约不变。
- `modelgate.personal-access.enabled` 在 [application.yml](../../src/main/resources/application.yml) 的 `modelgate.personal-access` 下显式默认为 `false`。行内由 Apollo 下发配置的环境可发布同名键，变更后滚动重启各实例，并通过 `GET /modelgate/personal-access/meta` 核对生效值。关掉时不允许新增/启用账户、签发 Key、授予/启用模型，也拒绝个人业务调用；仍可查看个人历史、停用/撤销。个人状态和权限变更按现有方式使本实例缓存失效；其它实例需等待缓存 TTL 收敛，操作后验收所有实例。不强行中止已有流式调用。
- 已有库先审核执行增量 DDL，再部署兼容后端（个人功能关闭）；新库直接用全量脚本。准备管理权限和前端后，只对试点人员打开。回退首选关个人开关并退到仍识别个人主体的兼容版本；不能假设更旧版本会识别开关或过滤个人记录。首次生产执行 SQL、开关及授权由现场人员审核，本功能开发不修改实际数据源、不执行生产 SQL。

## 6. 验收数据与判定

在**隔离测试库**录入 `MGQA_TEACHER_A`（测试老师甲）、`MGQA_TEACHER_B`（测试老师乙），以及保留前导零的数字系统 `00012001`。使用同一个虚拟模型 `mgqa-chat`，由本地模拟上游返回已知 usage，不调用真实模型。测试数据与复跑方式留在测试资源和说明中，不放入生产全量脚本。

测试数据见 `src/test/resources/personal-access/scenario.json`。在项目根目录运行 `mvn -Dtest=PersonalAccessIntegrationTest test`，用隔离 H2 库和本地模拟上游，通过管理接口录入账号，再从网关入口调用并核对入库审计。测试运行使用随机端口，库随测试进程退出销毁。TDSQL 的增量脚本另按现场数据库流程验证。

| 场景 | 验收 |
| --- | --- |
| 开户与重复录入 | 个人编号为 34 字符且两人不同；数字系统仍可用；重复大小写/空白变体 UM 不产生新记录。 |
| 调用和用量隔离 | 老师甲发两次（包含一次轮换后），老师乙和系统各发一次；模拟每次输入 12、输出 8，甲合计 40、乙 20，旧系统统计 20。流式、非流式均计到对应 UM。 |
| 无权调用 | 模型未授权、未解析到模型、调用 `/svc/**`、撤销 Key、停用个人或关闭开关时，不触达模拟上游。伪造 Header 不改变归属。 |
| 管理隔离 | 系统列表不显示个人；旧凭证/授权接口不能读取或修改个人；使用别人的 Key ID 不能越界撤销；个人 API 不暴露内部编号；不落个人报文。 |
| 存量回归 | 已有 API Key、AK/SK、模型和通用服务转发、路径、报表与两套页面仍按原约定运行。通过后端测试、前端权限/类型/构建和部署脚本静态检查。 |
