# ModelGate · 统一文根与路径迁移（2026-10-08，2026-10-09 修正）

## 约定

统一文根为 `/modelgate`（2026-10-09 已校正名称），删除 Controller 中手工拼接的公共前缀。
该前缀只由 WebFlux 添加一次；Controller 保持 `/models`、`/services` 等应用内资源路径。
本项目是 WebFlux，使用 `spring.webflux.base-path`，不用 Servlet 的 `context-path`。
Controller 的资源常量仍收口在 `constant.UrlConstant`，不逐个拼部署文根。

| 类型 | 对外地址（直连应用 / SLB 保留文根） |
|---|---|
| 管理资源 | `/modelgate/models/page`、`/modelgate/services/list` 等 |
| 模型流量（流式 / 非流式） | `/modelgate/v1/chat/completions`、`/modelgate/v1/embeddings` 等 |
| 通用 HTTP / SSE 服务 | `/modelgate/svc/{serviceId}/...` |
| 内置管理页 / 架构页 | `/modelgate/admin.html`、`/modelgate/architecture.html` |
| 运维端点（当前仅开放 health/info） | `/modelgate/actuator/health`、`/modelgate/actuator/info` |
| 容器探测 | `/modelgate/actuator/detection/running`、`available`、`shutdown` |

管理接口 `/modelgate/models/...` 等外部路径保持有效，前缀来源由 Controller 改为全局文根。
裸 `/v1/...`、裸 `/svc/...`、裸 `/admin.html` 等入口不再暴露，重复文根也不作为别名。
调用方、探针、权限表和部署路由必须使用正确文根；没有自动重定向。
这里的文根以应用当前配置为准；Actuator 与应用使用同一端口，未另开管理端口。

## 路径边界与安全

- Gateway 配置仍是 `Path=/v1/**` 和 `Path=/svc/**`。当前 Gateway 4.3.0 会读取
  WebFlux base-path 添加部署前缀，不要再把配置写成 `/modelgate/v1/**`。
- `ApplicationPaths` 使用框架确认的 `contextPath/pathWithinApplication` 获取应用内路径，
  不靠猜测字符串去掉文根。`TrafficType`、服务授权、服务路由与模型协议管线统一使用这一边界。
- 管理资源免业务鉴权的判定逐项列举 `UrlConstant.MANAGE_PATHS`，且匹配完整路径段。
  删除公共前缀后不能将空字符串或 `/` 作为内部路径前缀；`UNKNOWN` 仍需业务鉴权（fail-closed）。
- 模型上游永远不收到部署文根；通用服务 `stripPrefix=true/false` 都不收到 `/modelgate`。
  `stripPrefix=false` 保留的是应用内 `/svc/{serviceId}/...`，不是部署目录。
- 服务 / 授权 VO 的 `publicPrefix` 改为 `/modelgate/svc/{serviceId}`。
  历史报文既可能是 `/svc/...`，也可能是 `/modelgate/svc/...`；回放和最近路径推荐兼容两种记录，
  不需要改历史数据。服务编码与文根都按完整路径段剥离，不误剥相似前缀。
- 文根不提供身份保护。管理 API 仍由行内逐接口鉴权保护，静态页需单独授权，
  Actuator 尤其 shutdown 必须限制来源；不能把整个 `/modelgate/**` 免鉴权。
- 本次未新增超时或重试，通用服务仍不缓存/解析请求体，SSE flush 保持非阻塞。

## 两套管理前端

1. 内置页 `src/main/resources/static/admin.html`：API 使用应用内资源路径，
   `CTX_ROOT` 根据根目录中的页面地址确定实际入口。直连为 `/modelgate`；
   如果 SLB 还外挂 `/backend`，则为 `/backend/modelgate`。接入示例与 API 共用入口。
2. 独立项目 `D:\code\static-framework`，模块 `src/modules/modelgate`：
   `SERVICE_PREFIX.modelgate=/modelgate` 在 HTTP 客户端 baseURL 统一拼一次，
   模块 API 只写 `/models/...` 等；共享 `paths.ts` 处理 publicPrefix 与历史回放路径。
   接入示例使用 `VITE_MODELGATE_BASE_URL`，不从独立前端页面地址推断后端部署路径。

`VITE_MODELGATE_BASE_URL` 只填域名及 SLB 外部挂载目录，不要包含应用 `/modelgate`。
已有环境地址保持不变，前端路由 `/modelgate/...` 和菜单编码保持不变（不是后端 API）。
例如现有测试环境外部 `/backend/modelgate/modelgate/models/page` 中，`/backend/modelgate`
是 SLB 外挂目录，SLB 剥它以后必须把 `/modelgate/models/page` 传给应用。
这两个同名路径段分属 SLB 外挂目录和应用文根，不是 Controller 重复添加文根；
直连应用的地址始终是 `/modelgate/models/page`。本次未改动既有 SLB 外挂目录配置。
如果部署直接使用同域 `/modelgate`，前端配置仅填相应域名（同源可填空串，构建规则按环境处理）。

## 部署切换清单（外部配置未代为修改）

- [ ] SLB 路由按完整路径段匹配 `/modelgate` 并保留该段；仅剥自己的外部挂载目录。
- [ ] 容器 running / available / shutdown 与健康检查全部改为带 `/modelgate` 的地址。
- [ ] 行内应用网关 perm 表按 [13-管理接口权限清单.md](./13-管理接口权限清单.md) 的 54 个接口更新；
  若鉴权层在剥 SLB 前匹配 URL，还要带上该层看到的外部挂载目录。
- [ ] 同步两套管理前端、业务系统及 OpenAI SDK baseURL（通常为 `https://域名/modelgate/v1`）。
- [ ] 确认文根未被重复添加；确认匿名模型/服务请求仍被拒绝，静态页与探针走各自准入规则。
- [ ] 同步发布后端与调用方；回滚时也要协调回滚路径配置。

路径迁移本身没有增量 DDL，不自动执行任何 SQL，也不修改供应商的 upstreamUrl/upstreamPath。
此前 ProviderAdapter V2 的 SQL 升级仍按 [14](./14-ProviderAdapter-V2升级.md) 单独人工执行。

## 验证与关联修复

`ApplicationBasePathIntegrationTest` 启动隔离的随机端口 Netty/Gateway，模拟数据服务与上游，
验证管理页、健康检查、GET/POST 平台探针、裸/重复路径拒绝、模型鉴权与 URI/body、
服务鉴权及上游永不结束时的 SSE 首帧、stripPrefix=false 路径。无生产 DB/Redis/供应商调用。
`ApplicationPathsTest` 验证 URI 原始编码/query、全部管理资源边界、fail-closed 与历史路径。
现有模型 V2 本地上游测试也改用带文根的请求，覆盖原生 / OpenAI 响应及流式 / 非流式。
独立前端行为检查：`node scripts/test-modelgate-paths.mjs`；另执行类型检查、Lint 与构建。

真实链路测试发现现有 `BodyParseFilter` 在 `flatMap` 返回 `Mono<Void>` 后使用 `switchIfEmpty`，
成功请求完成也会落空流分支、再次执行过滤器链。改为完成标记后再判断实际空 body；
模型路由的降级读 body 分支同样修正，防止正常完成后又写空体错误。无重试策略变化。
