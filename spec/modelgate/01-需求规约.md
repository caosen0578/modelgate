## 1. 项目定位（必须理解，不得偏离）

**ModelGate** 是公司内网的 AI 模型流量分发网关，定位类比于外部 AI API 服务商（如 OpenAI），但服务对象是公司内部系统。

**核心职责三句话：**
1. 统一注册和管理内网部署的多个 AI 模型（含自建和外部 API）
2. 为每个内部接入系统颁发独立凭证，控制其可访问的模型范围
3. 对外暴露统一的 OpenAI 兼容接口，将请求路由并转发至对应上游模型

**不在范围内，禁止实现：**
- 禁止实现模型训练、微调功能
- 禁止实现用户个人账号体系（不是 C 端产品）
- 禁止实现跨公司/跨网络的外网访问能力
- 禁止在 v1 中实现计费系统（Token 统计仅用于审计）

## 2. 核心概念定义（AI 必须按此理解，不得重新解释）

| 概念 | 定义 | 对应表 |
|---|---|---|
| **模型（Model）** | 一个可被调用的 AI 服务实例；`model_id` 是网关对外路由 ID，`upstream_model_id` 是供应商真实 ID（可空，空则两者相同），并绑定上游地址和鉴权配置 | `mg_model` + `mg_model_credential` |
| **接入系统（App）** | 需要使用 AI 能力的内部业务系统，如风控系统、CRM 系统 | `mg_app` |
| **凭证（Credential）** | ModelGate 颁发给接入系统的访问密钥，类型为 API Key 或 AK/SK | `mg_app_credential` |
| **模型授权（Auth）** | 某个接入系统被允许访问某个模型，含限流和配额配置 | `mg_app_model_auth` |
| **访问控制（Access Rule）** | 对某接入系统的来源 IP 或域名的白名单限制 | `mg_access_rule` |
| **服务（Service）** | 与「模型」平级的**第二类上游目标**：接入系统的普通 HTTP / SSE 接口借本网关做鉴权与配额。对外路径 `/svc/{服务编码}/**`，`service_id` 即编码、**创建后不可修改**（它是 URL 的一段） | `mg_service` + `mg_service_credential` |
| **服务授权（Service Auth）** | 某个接入系统被允许访问某个服务，含 QPS 与日调用量限制。**没有月 Token**——服务不产生 Token | `mg_app_service_auth` |

> **模型与服务的本质差别**（决定了两者分表而非合表）：
> 模型的路由键在**请求体的 `model` 字段**，必须把 body 读全才能定路由；
> 服务的路由键在 **path 第二段**，一个字节的 body 都不用碰。
> 因此服务链路每请求开销比模型链路低一个量级。详见 [12-通用服务接入设计.md](./12-通用服务接入设计.md)。

## 3. 功能模块清单（Phase 1 必须实现）

### 3.1 模型管理

| 功能 | 说明 | 优先级 |
|---|---|---|
| 模型录入 | 填写名称、对外 model_id、可选 upstream_model_id、提供商、描述、上游地址、API 规范、上游鉴权方式 | P0 |
| 模型编辑 | 所有业务字段均可修改，含对外 model_id；改名时凭证/授权级联，历史审计/报文保留旧 ID | P0 |
| 模型启用/禁用 | 禁用后访问该模型返回 503，实时生效 | P0 |
| 模型删除 | 存在活跃授权时禁止删除，必须先撤销所有授权 | P0 |
| 连通性测试 | 向真实上游发送测试请求；请求体 model 使用 upstream_model_id（空则 model_id），返回连通状态和延迟 | P0 |
| 上游鉴权配置 | 支持 api_key / ak_sk / azure / none 四种方式 | P0 |
| 参数规范配置 | 支持 openai / azure_openai / anthropic / custom 四种规范 | P1 |
| 自定义参数映射 | api_spec=custom 时，JSON 配置字段映射规则 | P1 |
| 固定参数注入 | 配置强制注入参数，业务系统无法覆盖 | P1 |

### 3.2 接入系统管理

| 功能 | 说明 | 优先级 |
|---|---|---|
| 系统注册 | 录入 app_id、名称、负责人、联系方式、描述 | P0 |
| 系统启用/禁用 | 禁用后该系统所有凭证立即失效 | P0 |
| 系统删除 | 级联删除该系统的所有凭证、授权、访问规则 | P0 |

### 3.3 凭证管理

| 功能 | 说明 | 优先级 |
|---|---|---|
| 生成凭证 | 为接入系统生成 API Key 或 AK/SK，支持设置过期时间 | P0 |
| 凭证启用/禁用 | 单个凭证开关，不影响同系统其他凭证 | P0 |
| 凭证删除 | 立即失效 | P0 |
| 凭证展示规则 | API Key / SK 创建时明文展示一次，之后永不可查 | P0 |

### 3.4 模型授权管理

| 功能 | 说明 | 优先级 |
|---|---|---|
| 授权模型 | 为接入系统授权可访问的模型列表 | P0 |
| 授权开关 | 单个系统-模型授权的启用/禁用 | P0 |
| QPS 限制 | 每个授权配置每秒请求上限，0=不限 | P0 |
| 日调用限制 | 每日请求次数上限，0=不限 | P1 |
| 月 Token 配额 | 月 Token 消耗上限，0=不限 | P1 |
| 授权到期 | 设置到期时间，到期后等同于禁用 | P1 |

### 3.5 访问控制

| 功能 | 说明 | 优先级 |
|---|---|---|
| IP 精确匹配 | 精确 IP，如 `192.168.1.5`，适合办公区固定工作站 | P0 |
| CIDR 网段匹配 | 如 `10.244.0.0/16`，**K8s Pod 网段推荐此方式**（Pod IP 动态变化，精确 IP 不可用） | P0 |
| 域名白名单 | 精确域名，如 `crm.internal.com`，匹配请求 Origin 头 | P0 |
| 通配域名白名单 | 单级通配，如 `*.internal.com`，匹配 Origin 头中的子域 | P0 |
| 规则为空时不限制 | 白名单为空 = 不校验来源（适合 K8s 内部服务、完全信任场景） | P0 |

**K8s 部署说明：** 公司内网采用 K8s 容器编排，Pod IP / Node IP 动态变化，调用方分两类：
- **K8s 内部业务系统**：使用 CIDR 规则覆盖所在集群 Pod 网段（如 `10.244.0.0/16`）
- **办公区人工访问**：使用 ip 或 cidr 规则覆盖办公室固定 IP 段（如 `192.168.0.0/16`）
- **K8s 服务间无域名需求**：域名规则适用于浏览器发起的请求（携带 Origin 头）

### 3.6 流量网关

| 功能 | 说明 | 优先级 |
|---|---|---|
| 凭证鉴权 | API Key 查询 + AK/SK 签名验证 | P0 |
| 访问控制拦截 | IP/域名白名单校验 | P0 |
| 模型授权校验 | 校验接入系统是否有权访问目标模型 | P0 |
| QPS 限流 | Redis 令牌桶，按系统级别 | P0 |
| 动态路由 | 根据 model_id 路由到对应上游 | P0 |
| 模型 ID 映射 | 鉴权/授权/配额按对外 model_id；转发前将请求体 model 改为 upstream_model_id，响应不反向改写 | P0 |
| OpenAI 直透 | api_spec=openai 时不做供应商协议转换；仍执行上游模型 ID 映射及已配置的默认/强制参数 | P0 |
| Azure 适配 | URL/Header/参数适配 | P1 |
| Anthropic 适配 | 请求体和响应体全量转换 | P1 |
| 流式响应透传 | SSE 响应直接透传，不缓冲 | P0 |
| 熔断保护 | Resilience4j，按模型独立熔断 | P0 |
| 审计日志 | 每次请求异步入内存队列，批量写 MySQL（缓冲 200,000 条，2s 一批 5,000 条 batchInsert；无 MQ） | P0 |
| 审计日志清理 | 每天凌晨 2 点批量删除 90 天前数据（每批 10,000 行 + 200ms sleep，防锁表） | P1 |
| 用量统计查询 | GET /modelgate/stats/usage 返回总请求数、Token 消耗、平均延迟、成功率（按 appId/modelId/时间段） | P1 |

## 4. 对外接口约定（不得更改）

**业务系统调用 ModelGate 的格式，与 OpenAI SDK 完全兼容：**

```
POST /v1/chat/completions
Authorization: Bearer {api_key}
Content-Type: application/json

{"model": "{model_id}", "messages": [...], "stream": true}
```

内部系统只需修改 `base_url` 和 `api_key`，无需其他代码改动。

## 5. 开关优先级（必须按此实现，不得自行判断）

```
系统启用开关（mg_app.enabled）
  → 关闭：该系统所有请求拒绝，不再检查后续条件

凭证启用开关（mg_app_credential.enabled）
  → 关闭：该凭证的所有请求拒绝

凭证过期（mg_app_credential.expires_at）
  → 过期：该凭证的所有请求拒绝，返回 403，不删除记录

模型授权开关（mg_app_model_auth.enabled）
  → 关闭：该系统访问该模型返回 403

模型授权过期（mg_app_model_auth.expires_at）
  → 过期：等同于关闭

模型本身开关（mg_model.enabled）
  → 关闭：所有系统访问该模型返回 503
```

**执行顺序：系统开关 → 凭证开关 → 来源白名单 → 模型授权 → 模型状态 → QPS 限流**

## 6. 非功能性需求

### 6.1 性能指标

| 指标 | 目标值 |
|---|---|
| 鉴权 + 路由额外引入延迟 | < 5ms（本地 Caffeine 命中时） |
| 单实例吞吐 | ≥ 500 QPS（非流式），≥ 200 并发连接（流式） |
| 缓存刷新延迟 | 管理请求所在实例提交后主动失效；其他实例模型/上游凭证 ≤30s，授权/白名单/系统信息 ≤60s |
| 审计写入延迟 | 最大 2s（队列缓冲，不阻塞主链路） |

### 6.2 安全要求

| 要求 | 实现约束 |
|---|---|
| 密钥加密存储 | 上游 API Key / SK 使用 AES-256-GCM 加密后入库，密钥从环境变量注入 |
| Secret 仅展示一次 | SK / API Key 创建时明文响应一次，DB 中只存哈希摘要/密文 |
| 常量时间比较 | API Key 鉴权使用 `MessageDigest.isEqual`，防时序攻击 |
| AK/SK 防重放 | 签名携带时间戳，±5 分钟窗口外请求直接拒绝 |
| 日志脱敏 | 任何日志中禁止出现完整 API Key / SK 明文 |

### 6.3 高可用

- 网关层无状态，可水平扩展（K8s Deployment）
- 凭证/授权/访问规则/模型配置的真实读取链为 Caffeine → MySQL，不经过 Redis L2；L1 miss 原子回源 MySQL
- 当前无跨实例缓存失效广播，管理变更所在实例主动失效，其他实例按模型/凭证 30s、授权/规则 60s TTL 收敛
- QuotaFilter Redis 不可用时 fail-open（配额检查跳过，请求继续）
- 上游模型故障触发 Resilience4j 熔断，熔断期间返回 503，60s 后自动进入半开探测（`waitDurationInOpenState=60s`）

### 6.4 可扩展性

- 新增模型提供商：只需实现 `ProviderAdapter` 接口
- 新增参数转换规则：通过 `param_mapping` JSON 配置，无需改动代码
- 新增访问规则类型：在 `AppAccessControlFilter.isAllowed()` + `IpMatcher` 中扩展
