# 模型与个人用量统计

「模型网关 → 用量统计」通过 `/modelgate/stats/model-usage` 和 `/modelgate/stats/user-usage` 查询。两页取模型流量的审计行，统计请求数、输入和输出 Token、上游返回和估算的 Token、缺少 Token 的请求数。筛选范围内的汇总涵盖所有页。日期沿用网关审计时间，历史范围受审计保留期约束。

- 模型用量按审计中的模型 ID 汇总，全部来源包含个人 Key、接入应用及 CodeBuddy。可使用具体应用 ID 缩小范围。
- 个人用量按 UM 汇总，同一 UM 的个人 Key 与 CodeBuddy 用量合计，展开后查看模型和来源。普通共享应用的用量保留在模型报表。
- CodeBuddy 来源采用验证通过的接入应用 ID 白名单，默认 `95731`。网关在生成审计时保存该应用提供的 UUID。一次调用的一条审计只汇总一次，TraceID 用于排查。UUID 和 Token 采集独立于报文记录开关。
- 未匹配映射的 CodeBuddy 调用归入「未归属」。个人 UM 来自用户接入资料或行为服务维护的 UUID 映射，映射调整会反映到报表中。CodeBuddy 客户端提供的 UUID 用于用量归属，应用凭证继续决定网关鉴权。

## 部署

1. 存量网关数据库先执行 `sql/upgrade_20261117_codebuddy_usage_identity.sql`，新库从全量脚本创建。
2. 在行为服务与网关配置相同的 `modelgate.usage.codebuddy.identity-token`。在网关配置 `modelgate.usage.codebuddy.identity-url` 为行为服务的内部可达地址，例如 `https://behavior.internal/api/analysis/out/modelgate/codebuddy-identities`。按目标环境核对 `modelgate.usage.codebuddy.app-ids`。未开通映射接口的环境仍可以查询模型与个人 Key 用量。
3. 用户库执行 27 号权限增量，为角色授予菜单、各自查询接口和所需筛选选项。
4. 部署行为服务、网关和分离管理前端。
5. 如需回补历史 CodeBuddy 审计，核对 `sql/repair_20261117_codebuddy_usage_identity.sql` 的应用和时间，选定时间段执行。脚本只补仍有留档、同一应用和模型下 TraceID 在两表均唯一、时间相近且可识别 UUID 的调用，并保留已有归属。
