# Spec Me2AI · 13 · 管理接口权限清单（perm 表录入依据）

> **文档性质**：接口清单由 `PermInventoryTest --dump` **反射生成**，分级人工判定。
> 该用例同时是漂移守卫：清单与代码不一致即失败。
>
> **用途**：内网应用网关按 perm 表逐接口拦截前端访问，本清单是录入依据。

## 为什么这份清单是可靠的

管理面**刻意**设计成可被外部 RBAC 接管，三条既有约束共同保证：

| 约束 | 出处 | 对 perm 的意义 |
|---|---|---|
| 本进程对 `/modelgate/**` 不做任何身份校验 | 05 §6.1 | 拦截权完全在网关侧，不会出现两处鉴权打架 |
| 禁止 Controller 使用 `@PathVariable` | 05 §9（理由原文：**RBAC 按固定路径绑定**） | 每条路径都是编译期常量，可逐条录入，不需要通配 |
| 路径统一收口在 `UrlConstant` | 05 §9 | 改路径 = 改契约需评审，perm 不会被静默改漂 |

> 换句话说：**你要的"按功能角色控制管理接口"，本项目不需要改任何代码**，
> 把下面 53 条录进 perm 即可。

## ✅ 已解决：perm 按 path 还是按 path + method 都可以

本文档此前登记过一个待确认项：有 **3 条路径同路径不同方法**，且每条都是「只读 vs 写」撞在一起
（`GET /modelgate/apps` 列表 vs `POST /modelgate/apps` 新建，models / services 同理）。
若内网 perm 只按 path 匹配，这 3 条无法区分，等于**把新建权限给到所有能看列表的人**。

**2026-09-10 已消除**：接口路径显式化改造（见 11 §37）把集合根上的读写都挪到了独立路径——
`GET /modelgate/apps/page` 与 `POST /modelgate/apps/create` 不再共用一个 path。

> **现在全部 53 条路径两两不同**，perm 无论按 path 还是按 path + method 录入都不会产生歧义。
> 这个性质需要保持：**新增接口时不要再让读写共用同一条路径**，
> 否则这个坑会在没人注意的情况下回来。

## ⚠️ 静态页面不在 `/modelgate` 前缀下

`admin.html` 与 `architecture.html` 由 WebFlux 默认资源处理器暴露在**根路径**。
只拦 `/modelgate/**` 会漏掉页面本身——页面访问权限需在网关侧单独配一条。

## 分级建议（角色绑定）

| 级别 | 条数 | 建议角色 | 理由 |
|---|---|---|---|
| L1 | 18 | 查看者 | 不改任何状态 |
| L2 | 9 | 运维 | 启停直接影响线上流量；三个 test 会真实打上游、消耗 token |
| L3 | 21 | 管理员 | 增删改。其中 `access/delete` 与 `services/update` 危害最大 |
| L4 | 2 | 单独审批 | 拿到即可冒充调用方，业务面四层防护全部无效 |
| L4 | 3 | 单独审批 | 留档里就有别人的凭证头，且可模糊检索 |

> **L4 必须与 L3 分开**：能改配置的人不一定该看得到别人的密钥明文。
> `credentials/secret` 拿到的凭证可直接冒充该 `appId` 调 `/v1/**`——
> 凭证鉴权、访问控制、模型授权、配额四层对它<b>全部无效</b>。

## 维护约定

新增管理接口时**必须同步本清单**，否则它在 perm 里没有条目——
取决于网关默认策略，要么无人可用（新功能上线即报无权限），
要么**无保护**（谁都能调，且不会有任何报错提示你漏了）。后者是安静失败。

重新生成：`java -cp <test-classes>:<classes>:<deps> com.pab.ficc.ibp.modelgate.server.controller.PermInventoryTest --dump`
