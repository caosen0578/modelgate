FULL 与 TAIL

需要留档的响应走 FULL；非流式响应也走 FULL 以解析 usage。未开启留档的 SSE 只保留尾部 64 KiB 做用量解析，不把尾巴当完整报文入库。全局关闭时 PayloadService 不入队。

采集与持久化保护

FULL 默认保护阈值 64 MiB（可配置，按块判断），达到后停止后续采集但继续转发，标记 truncated=response。主队列和重试缓冲均有上限，进程异常退出仍可能丢失未落库数据，不是持久消息队列。

独立的审计与清理

AuditService 独立批量写 mg_audit_log，保存状态、耗时、Token 和来源口径，并异步累加月 Token。PayloadCleanupService 按配置保留期分批删除报文，实际配置可查 /modelgate/payload/meta。

请求正文的现有边界：模型 POST JSON 由 BodyParseFilter 缓存原始正文。通用 HTTP/SSE 服务链路刻意不读取 body，因此目前通常只留档方法、路径、请求头和响应，request_body 为空；这不是通用服务的完整请求镜像。
非流式服务开关的现有例外：非流式响应直接选择 FULL，而服务留档分支只检查 FULL 模式；因此全局录制开启时，即使该服务的录制开关关闭，非流式响应仍可能入库。图中如实标注该现状，本次未修改此行为。
敏感数据：当前请求头快照包含 Authorization / Cookie / Token，正文可能包含用户输入与模型输出，尚未脱敏。报文查询、详情、数据库访问及保留期必须受控；页面可查看不代表可以向所有员工开放。

核对项当前行为排障含义
网关业务规则跳过调用方凭证、来源规则、模型/服务授权、配额和业务熔断链。适合排查上游；不能用来复现网关拦截的 401 / 403 / 429。
历史请求头只供查询留档，不自动注入回放；使用当前上游凭证和配置头。依赖原 Cookie、自定义 Header 或签名的请求，可能无法等价复现。
通用服务请求体历史正文通常未采集；无手工正文且无留档正文时，Controller 会拒绝回放，连原本无 body 的 GET 也受此校验。不能把页面上的“回放”理解为任意历史 HTTP 请求都能一键重发。
路径还原默认从历史路径剥掉文根与服务前缀；路径可能因列长被截断，旧记录也可能缺失。stripPrefix=false、缺失或截断的历史路径，需人工核对并显式填写 path。
审计与配额输出回放 WARN 日志；不新增业务审计/报文记录，也不扣调用方网关配额。上游真实调用和计费仍发生；不能据网关用量表判断此次回放成本。
生产操作警告：回放可能再次写入业务数据、触发外部动作或消耗模型 Token；没有自动幂等保障。需限制回放权限，并核对目标环境、请求内容与上游副作用。

要验证完整网关链路？

使用接入系统凭证重新调用 /modelgate/v1/** 或 /modelgate/svc/**（接入示例 / 测试连通），而不是使用报文回放接口。那条链路才会执行调用方鉴权、授权、配额、熔断和审计。
